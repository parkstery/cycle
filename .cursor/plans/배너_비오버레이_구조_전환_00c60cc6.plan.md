# 배너 비오버레이 구조 전환 계획

## 추가 분석 결론

- 현재 앱은 [BridgeActivity.java](C:/20.HDev/cycle/node_modules/@capacitor/android/capacitor/src/main/java/com/getcapacitor/BridgeActivity.java)에서 `setContentView(R.layout.capacitor_bridge_layout_main)`를 사용하므로, 앱의 [activity_main.xml](C:/20.HDev/cycle/android/app/src/main/res/layout/activity_main.xml)은 실제 루트로 쓰이지 않습니다.
- Capacitor AdMob 플러그인은 [BannerExecutor.java](C:/20.HDev/cycle/node_modules/@capacitor-community/admob/android/src/main/java/com/getcapacitor/community/admob/banner/BannerExecutor.java)에서 `android.R.id.content`의 루트에 배너 호스트를 `addView`하므로 오버레이가 구조적으로 발생합니다.
- 따라서 요구사항(오버레이 금지, XML 세로 구조 강제)을 만족하려면 플러그인 오버레이 경로를 배제하고 앱이 소유한 레이아웃에 배너를 고정 배치해야 합니다.

## 구현 방향(확정)

- 배너는 `@capacitor-community/admob`의 `showBanner/removeBanner` 경로를 쓰지 않고, Android 네이티브에서 직접 `AdView`를 관리합니다.
- 레이아웃은 앱 리소스 XML에 `LinearLayout(vertical)` + `WebView(height=0dp, weight=1)` + `AdViewContainer(wrap_content)` 구조로 고정합니다.
- `MainActivity`의 WebView bottom padding 조작은 제거합니다.
- `App.tsx`의 safe-area/bottom padding 기반 배너 보정은 제거합니다.

## 작업 단계

1. Capacitor 기본 레이아웃 오버라이드

- 파일 추가: [capacitor_bridge_layout_main.xml](C:/20.HDev/cycle/android/app/src/main/res/layout/capacitor_bridge_layout_main.xml)
- 동일 리소스명으로 Capacitor 기본 레이아웃을 오버라이드하여 아래 구조 적용:
  - `LinearLayout`(vertical, match_parent)
  - `com.getcapacitor.CapacitorWebView` (`@id/webview`, width=match_parent, height=0dp, weight=1)
  - `FrameLayout` (`@id/native_ad_container`, width=match_parent, height=wrap_content)

1. MainActivity 네이티브 배너 고정 배치

- 파일 수정: [MainActivity.java](C:/20.HDev/cycle/android/app/src/main/java/com/liveonsoft/cycle/MainActivity.java)
- 제거 대상:
  - WebView bottom padding 계산/적용(`WindowInsets + bannerHeight` 합산 로직)
  - 배너를 최상단으로 올리는 레이어 재정렬 코드
- 추가 대상:
  - `native_ad_container`를 찾아 `AdView`를 삽입/교체
  - `onResume/onConfigurationChanged`에서 배너 크기 재요청(Adaptive)
  - 배너 실패 시 컨테이너 `GONE`, 성공 시 `VISIBLE`
  - window inset은 루트 좌/상/우만 적용(하단은 컨테이너가 실제 공간 차지)

1. JS 배너 호출 경로 정리

- 파일 수정: [App.tsx](C:/20.HDev/cycle/App.tsx)
- 배너 show/hide/remove 호출 로직 제거 또는 no-op화:
  - `AdMob.showBanner/removeBanner/hideBanner` 호출 비활성화
  - 배너 이벤트 리스너(`bannerAdLoaded`, `bannerAdFailedToLoad`, `bannerAdSizeChanged`) 제거
- 인터스티셜/리워디드가 필요하면 해당 경로는 유지(배너만 네이티브 직접 관리)

1. 웹 하단 보정 완전 제거

- 파일 수정: [App.tsx](C:/20.HDev/cycle/App.tsx), [MenuPanel.tsx](C:/20.HDev/cycle/MenuPanel.tsx)
- `env(safe-area-inset-bottom)` + 배너 예약값 기반 보정 제거
- 맵/저작권/UI 하단 위치는 고정 최소 오프셋만 유지

1. 검증 시나리오

- 기기: S22, N935K
- 케이스: 세로/가로, 앱 시작 직후, 회전 직후, 배너 로드 성공/실패
- 합격 기준:
  - 배너는 항상 맵 아래(오버레이 없음)
  - 맵 UI/저작권이 배너에 가려지지 않음
  - WebView bottom padding 조작 없이도 검은 공백 바 미발생

## 리스크 및 대응

- Capacitor 리소스 오버라이드 충돌 가능성: 동일 리소스명(`capacitor_bridge_layout_main`) 오버라이드 방식으로 최소 변경.
- 배너 직접 관리 시 SDK 초기화 누락 위험: `MobileAds.initialize`와 `AdView` 생명주기(`pause/resume/destroy`)를 MainActivity에서 명시적으로 처리.
- 배너 실패 시 빈 공간 위험: 실패 시 `native_ad_container`를 `GONE` 처리해 공간 즉시 회수.
