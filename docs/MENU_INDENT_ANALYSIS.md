# MenuPanel.tsx GUIDE/LEGAL 하위 항목 들여쓰기(Indent) 분석 보고

## 1. 현재 코드에서의 의도된 레이아웃

### 1.1 구조 요약

- **최상위 리스트**: `<ul className="py-2 text-slate-800 list-none pl-0">`
  - `pl-0` → 리스트 전체의 왼쪽 패딩이 0. 리스트 내용의 “기준선”이 패널 왼쪽 끝(0)에 맞춰져 있음.

- **1레벨 항목** (About, Settings, Contact)  
  - 버튼: `px-4`  
  - **텍스트 시작 위치**: 패널 왼쪽 기준 **16px (1rem)**.

- **카테고리 헤더** (Guide, Legal)  
  - `<li className="px-4 ...">`  
  - **텍스트 시작 위치**: 동일하게 **16px**.

- **하위 리스트** (GUIDE 하위: Quick Guide, Detailed Guide / LEGAL 하위: Privacy Policy 등)  
  - 감싸는 `<ul className="border-l-2 border-slate-200 ml-4 pl-4 my-0.5 list-none">`
    - `ml-4` → 이 `<ul>` 박스가 왼쪽으로부터 **16px** 떨어져 시작.
    - `pl-4` → 그 안쪽으로 **16px** 패딩.
    - 따라서 **ul 내용(버튼 영역) 시작**: 16px + 16px = **32px**.
  - 하위 버튼: `pl-2 pr-4`
    - **하위 항목 텍스트 시작**: 32px + 8px = **40px**.

즉, 코드 의도상:

- 1레벨/헤더: **16px**
- 하위 항목: **40px**  
→ 하위가 **오른쪽으로 들여쓰기(indent)** 되도록 되어 있음.

---

## 2. “Outdent처럼 보이는” 현상이 나올 수 있는 이유

수치만 보면 하위 항목이 더 오른쪽(40px)에 있어야 하는데, 화면에서는 **반대로 왼쪽으로 들어간 것처럼(outdent)** 보일 수 있는 요인들입니다.

### 2.1 시각적 기준점과 세로선(border-l-2)

- GUIDE/LEGAL **헤더 텍스트**와 하위 `<ul>`의 **왼쪽 세로선(border-l-2)** 이 같은 **16px**에서 시작함.
- 세로선이 “들여쓰기 구역의 시작”처럼 보이면서, 실제 하위 텍스트(40px)와의 거리(24px)가 작게 느껴질 수 있음.
- 상대적으로 “헤더와 같은 줄” 또는 “오히려 왼쪽으로 나온 것처럼” 느껴질 수 있음 (특히 폰트/해상도에 따라).

### 2.2 하위 버튼의 왼쪽 여백이 작음 (pl-2)

- 하위 항목 버튼은 **pl-2**(8px)만 있어서, ul 내용 시작(32px)에서 텍스트까지의 거리가 짧음.
- 1레벨은 **px-4**(16px)로 여백이 더 크기 때문에, “1레벨이 더 들여쓰기된 것처럼” 보이는 착시가 생길 수 있음.
- 즉, **실제 픽셀은 하위가 더 오른쪽인데, 시각적으로는 1레벨이 더 들어가 보이는** 상황이 가능함.

### 2.3 방향성(dir) 및 논리 속성 미사용

- `index.html`에 `dir="rtl"` 없음 → 기본 LTR.
- 다만, 모든 여백이 **물리적 left** (`pl-*`, `ml-4`)로만 되어 있어서:
  - 나중에 RTL이나 `dir`이 상위에서 지정되면, “들여쓰기”가 반대 방향으로 적용될 수 있음.
  - 그 경우 **indent가 outdent처럼** 보일 수 있음.

### 2.4 다른 CSS/빌드의 간섭

- 전역 스타일에서 `ul/li`의 `margin`/`padding`을 덮어쓰면, `ml-4`/`pl-4`가 무효화되거나 반대로 적용될 수 있음.
- 캐시/빌드 때문에 예전 버전의 MenuPanel(예: 다른 pl/ml 값)이 로드되면, 의도와 다르게 보일 수 있음.

## 3. 원하는 Indent가 확실히 적용되도록 하기 위한 제안

코드는 작성하지 않고, **어디를 어떻게 맞추면 좋은지**만 정리합니다.

### 3.1 기준선을 명확히 맞추기

- **1레벨과 카테고리 헤더**는 동일한 왼쪽 여백(현재 `px-4` = 16px)을 유지.
- **하위 리스트**만 “그 기준선에서 추가로 오른쪽으로” 가도록 유지하되, **차이를 더 크게** 주는 것이 좋음.
  - 예: inner `<ul>`의 `pl-4`를 `pl-6` 또는 `pl-8`로 늘려서, 하위 텍스트가 1레벨보다 확실히 오른쪽에 오도록 함.
  - 또는 하위 버튼의 `pl-2`를 `pl-4`로 맞춰서 1레벨과 같은 “텍스트 전 여백”을 주면, 세로선과 텍스트 사이가 벌어져 계층이 더 분명해짐.

### 3.2 “Outdent 착시” 줄이기

- 하위 항목의 **왼쪽 여백**을 1레벨보다 작지 않게 유지하는 것이 좋음.  
  (현재 1레벨 16px, 하위는 32px+8px=40px라 수치상은 괜찮지만, 시각적으로는 하위 버튼의 `pl-2`를 `pl-4` 정도로 키우면 “같은 레벨처럼 보이는” 느낌을 줄일 수 있음.)
- 세로선(`border-l-2`)을 유지하면서, **세로선 ~ 하위 텍스트** 사이 간격을 넓히면 “들여쓰기 구역”이 더 명확해짐.

### 3.3 논리 속성으로 방향 독립적으로 만들기

- `pl-*` / `ml-4` 대신 Tailwind의 **inline-start** 계열 사용 권장:
  - `ps-4`, `ps-6`, `ms-4` 등 (`padding-inline-start`, `margin-inline-start`).
- 이렇게 하면 LTR/RTL 모두에서 “시작 쪽에 들여쓰기”가 적용되어, RTL 환경에서 indent가 outdent처럼 보이는 문제를 예방할 수 있음.

### 3.4 점검할 부분

- **실제 로드되는 파일**: `MenuPanel.tsx`가 맞는지, 다른 버전(예: MenuPanel-cur3.tsx)이 쓰이지 않는지 확인.
- **전역 CSS**: `ul`, `li`, `.menu` 등에 `margin`/`padding`을 주는 규칙이 없는지 검사.
- **개발자 도구**: 메뉴가 열린 상태에서 하위 항목의 `<ul>`, `<button>`에 적용된 `margin`/`padding`을 확인해, `ml-4`/`pl-4`/`pl-2`가 예상대로 적용되는지 확인.

---

## 4. 요약

- **현재 코드**는 1레벨 16px, 하위 40px로 **수치상 하위가 더 오른쪽(indent)** 이 맞음.
- **Outdent처럼 보일 수 있는 요인**:  
  (1) 세로선과 헤더가 같은 16px에 있어 시각적 기준이 혼동됨,  
  (2) 하위 버튼의 `pl-2`로 인한 착시,  
  (3) RTL/다른 CSS·빌드 간섭.
- **원하는 indent를 확실히 하려면**:  
  하위 쪽 `pl`/`padding-inline-start`를 키우고, 가능하면 `pl`/`ml`을 논리 속성(`ps`/`ms`)으로 통일해 보는 것을 권장함.
