## 2. `speak` 진입 조건·전처리

**위치:** `App.tsx` 내 `useCallback`으로 정의.

1. **`coachingOn`이 false면 즉시 return**  
   - 마이크 버튼으로 끈 상태에서는 **어떤 `speak(...)` 호출도 소리를 내지 않는다.**  
   - `setCoachData` 등 UI 갱신은 호출부에서 `coachingOn`과 무관하게 일어날 수 있음(코칭 표시 보고서 참고).

2. **문자열 정규화**  
   - `(text || '').trim()`  
   - 빈 문자열이면 return.

3. **요청 ID (`speechRequestIdRef`)**  
   - 매 호출마다 `++speechRequestIdRef.current`로 **고유 `requestId`** 부여.  
   - 비동기·타이머·`onstart`/`onerror` 콜백 안에서 **`speechRequestIdRef.current !== requestId`이면 중단** — 연속 호출 시 **이전 발화**가 새 발화를 덮어쓰지 않도록 한다.

4. **플랫폼**  
   - `Capacitor.isNativePlatform()` → 네이티브일 때만 Capacitor TTS 폴백 경로를 사용할 준비를 한다.

5. **즉시 취소 후 재생 준비**  
   - `getSpeechSynthesisSafe()`로 Web Speech API 사용 가능 여부 확인.  
   - **`safeSpeechCancel()`**을 **항상 먼저** 호출 → 직전 웹 utterance·타이머·네이티브 TTS를 정리한 뒤 새 발화를 스케줄한다.

## 3. `safeSpeechCancel` / `stopNativeSpeech`

### 3.1 `safeSpeechCancel`

- `speechStartTimeoutRef`가 있으면 clear(웹 TTS가 1.2초 안에 `onstart`를 안 주는지 감시하던 타이머).
- `window.speechSynthesis.cancel()` (가능할 때).
- **`void stopNativeSpeech()`** — 네이티브에서 진행 중인 `TextToSpeech`를 멈춤.

### 3.2 `stopNativeSpeech`

- `Capacitor.isNativePlatform()`일 때만 `TextToSpeech.stop()` await.  
- 실패는 로그만.

### 3.3 호출되는 시점(대표)

| 시점 | 동작 |
|------|------|
| **매 `speak` 호출 직전** | 이전 발화/대기 타이머 정리 |
| **`coachingOn`이 false로 바뀔 때** (`useEffect`) | 사용자가 코치 음소거 → 진행 중 음성 즉시 중단 |
| **`handleStopSimulation`(유저 Stop)** | 주행 종료 시 `safeSpeechCancel()`로 남은 TTS 정리 |

일시정지(Pause) 전용으로 `safeSpeechCancel`을 부르는 코드는 **검색상 없음** — 일시정지해도 **이미 시작된 한 문장**은 끝까지 나갈 수 있다.

## 4. Web Speech API 우선 경로

`getSpeechSynthesisSafe()`가 null이 아니면 아래를 **50ms 지연** 후 실행한다.

**이유(코드 주석):** `cancel` 직후 곧바로 `speak`하면 일부 브라우저에서 재생이 누락될 수 있어 `setTimeout(scheduleSpeak, 50)`으로 한 템포 비운다.

### 4.1 `SpeechSynthesisUtterance` 설정

- `utterance.lang = 'en-US'`  
- `getVoices()` 후 **선호 음성:** `lang`이 `en`으로 시작하고 이름에 `Female` / `Google US English` / `Samantha` 포함 시 선택.  
- `utterance.rate = 1.0` (피치는 기본).

### 4.2 이벤트

- **`onstart`:**  
  - `requestId` 일치 시 `webStarted = true`, `speechStartTimeoutRef` 클리어.  
  - 웹 TTS가 실제로 시작됐음을 표시.

- **`onerror`:**  
  - `requestId` 일치 시 로그 후 **`fallbackToNative('web_error')`**.

### 4.3 네이티브 앱에서의 “시작 타임아웃”

- `isNativePlatform`이 true이면 `synth.speak(utterance)` 직후 **1200ms 타이머**를 건다.  
- 타이머 시점에 여전히 `!webStarted`이면 **`fallbackToNative('web_start_timeout')`** — Android WebView 등에서 웹 Speech가 **시작 콜백 없이** 무반응인 경우 Capacitor TTS로 넘긴다.

### 4.4 `synth.speak` 예외

- try/catch에서 실패 시 `fallbackToNative('web_speak_exception')`.

### 4.5 `fallbackToNative`

- 이미 한 번만 실행(`fallbackTriggered`).  
- 타임아웃 정리, `synth.cancel()`, **`speakNative(reason)`** 호출.

## 5. Web Speech 불가 시: 순수 네이티브 `speakNative`

`getSpeechSynthesisSafe()`가 **null**이면 곧바로 `void speakNative('web_unavailable')` 후 return.

`speakNative` 내부:

1. 네이티브 플랫폼이 아니면 return(웹인데 synth도 없으면 할 수 있는 것 없음).
2. `TextToSpeech.speak({ text: normalizedText, lang: 'en-US', rate: 1.0, pitch: 1.0, volume: 1.0 })`  
3. 실패 시 **`ko-KR`**로 한 번 더 시도(폴백).  
4. 각 await 전후로 `speechRequestIdRef.current !== requestId`이면 return — 새 `speak`가 끼어들면 이전 네이티브 시퀀스는 중단.

**언어:** 코칭 문구는 영어 풀(`phraseManifest`)이지만, 네이티브 1차는 `en-US`, 실패 시 `ko-KR`로 **엔진만** 바꾸고 **텍스트는 그대로** 읽는다(내용은 여전히 영어 문자열).

## 6. `speakRef`와 카운트다운 웜업

- `speak`는 `useCallback`으로 나중에 정의되므로, **그보다 앞선 effect**에서는 `speakRef.current`를 사용한다.  
- `useEffect([speak])`에서 `speakRef.current = speak`로 동기화.

**카운트다운:** `countdown === 3`일 때 `speakRef.current?.('Ready')`로 **짧은 웜업 발화** — Android WebView + Capacitor TTS cold-start 지연을 줄이기 위함(주석).  
- 이때도 **최종적으로는 정의된 `speak`가 실행**되므로 `coachingOn`이 꺼져 있으면 `'Ready'`도 나가지 않는다.

---

## 7. `voiceschanged` 리스너

- `getSpeechSynthesisSafe()`가 있으면 `voiceschanged`에 핸들러 등록 후 한 번 `getVoices()` 호출.  
- Chrome 등에서 초기 `getVoices()`가 빈 배열인 문제緩和 — `speak` 시점의 선호 음성 탐색 성공률을 높이려는 목적.

---

## 8. 앱에서 `speak`를 부르는 모든 경로

| 호출부 | 내용 | `coachingOn` 영향 |
|--------|------|-------------------|
| 주행 effect — 캐시 히트, 저항 변경 | `speak(currentCached.coaching.tip)` | 꺼져 있으면 무음 |
| 주행 effect — 30초 주기 재추첨 | `speak(fresh.displayText)` | 동일 |
| 주행 effect — safety net | `speak(newCoaching.tip)` | 동일 |
| `startSimulationCore` | 첫 코칭 `speak(coaching.tip)` | 동일 |
| 경로 끝 | `getRideEncouragement(...).then(speak)` | 격려 멘트도 동일 게이트 |
| Go/시작 흐름 | `getCourseBriefing(route).then(speak)` | 브리핑도 동일 게이트 |

즉 **`speak` 하나가 “코칭 전용”이 아니라 앱 내 고정 문구 TTS 공용 파이프**이며, **음소거는 전부 `coachingOn`으로 통제**된다(이름은 “Mute coach”이지만 briefing/격려도 같이 막힘).

## 9. 코칭 멘트 생성 쪽과의 연결(요약)

- 텍스트는 `getAdvancedCoaching` / `pickFreshTipForResistance` 등에서 **`"... (R3)"` 형태의 한 문자열**로 만들어진다.  
- TTS는 **괄호·숫자를 그대로 읽을 수 있음** — Web/네이티브 엔진에 따라 “R three”처럼 들릴 수 있음.  
- **`tipId` / `resId`**는 `CoachingData` 확장 필드로 존재할 수 있으나, **현재 `speak` 경로는 ID가 아니라 최종 `tip` 문자열 전체**를 넘긴다.

자세한 트리거(캐시·prefetch·주기)는 **코칭 표시 보고서** 절 4~5를 보면 된다.

---

## 10. BGM과의 관계 (BGM 보고서 정합)

- BGM은 `audioRef`의 **`new Audio()`** 한 개로 Dropbox MP3를 재생한다.  
- 코칭 TTS는 **브라우저 SpeechSynthesis 또는 Capacitor TextToSpeech** — **서로 다른 오디오 파이프라인**이다.  
- **`speak` 구현 안에는 BGM 볼륨 조절(`fadeAudio`)·`pendingAudioPauseRef` 터치가 없다.**  
- 따라서 주행 중 음악 ON + 코칭 ON이면 **음성과 BGM이 동시에 들릴 수 있으며**, 앱 레벨 **덕킹(ducking)** 은 구현되어 있지 않다.

## 14. 한계·개선 여지

1. **언어/음성:** 웹은 en 선호 목록 고정, 네이티브는 en-US 실패 시 ko-KR. 사용자 로케일 자동 반영은 없음.  
2. **동시 재생:** BGM과 레벨 밸런스 없음.  
3. **`coachingOn` 명칭:** 코칭 음소거인데 briefing/종료 격려까지 차단.  
4. **일시정지:** TTS 중간 취소는 Stop·음소거에 가깝고 Pause와 연동되지 않음.  
5. **캐시 MP3:** `audioCache` 미사용으로 네트워크/엔진 의존 TTS만 사용.
