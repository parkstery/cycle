# BGM(배경음악): 주행 중 음악 재생 로직 보고서

**작성일:** 2026-05-14  
**대상 코드:** `App.tsx` (단일 컴포넌트 내 인라인 구현)  
**요약:** 시뮬레이션(주행)이 **활성**이고 사용자가 음악을 **켠** 상태일 때만, 프로그래밍 방식으로 생성한 `HTMLAudioElement`로 Dropbox 호스팅 MP3를 순차·랜덤 재생한다. 모바일 WebView에서 `ended` 이벤트가 누락되거나 끝 구간에서 멈추는 경우를 보완하기 위해 **끝 근접 감지 + 워치독 + visibility 복구**가 함께 동작한다.

---

## 1. 개념 모델

| 용어 | 의미 |
|------|------|
| **주행 중** | React state `simulation.isActive === true` (일시정지·정지·한도 도달 등으로 `false`가 되면 “주행 중”이 아님) |
| **음악 ON** | `musicOn === true` (UI의 음악 아이콘 버튼으로 토글) |
| **실제 재생 조건** | `simulation.isActive && musicOn` 이 동시에 만족될 때만 새 트랙을 시작하고, 끝에서 다음 곡으로 넘긴다. |

BGM은 **코칭(TTS)** 과 별도 채널이며, 코칭 on/off(`coachingOn`)와 무관하게 동작한다.

## 2. 정적 데이터·튜닝 상수

### 2.1 플레이리스트 `PLAYLIST`

- **위치:** `App.tsx` 상단 모듈 스코프 (`PLAYLIST` 배열).
- **내용:** Dropbox 공유 링크 형태의 MP3 URL 다수(현재 **16곡**). `dl=1` 쿼리로 직접 다운로드/스트리밍에 적합한 형태.
- **역할:** `pickRandomTrack`이 이 배열에서 다음 재생 URL을 고른다. 앱 백엔드를 거치지 않고 클라이언트가 URL에 직접 `GET`한다.

### 2.2 WebView·브라우저 이슈 대응용 상수

코멘트에 명시된 대로, **일부 WebView에서 `ended`가 안 오거나 끝에서 재생이 멈추는** 경우를 대비한다.

| 상수 | 값 | 용도 |
|------|-----|------|
| `BG_MUSIC_NEAR_END_SEC` | `0.38` | `duration - 0.38`초 이후를 “거의 끝”으로 본다. `timeupdate`·`visibility` 복구에서 사용. |
| `BG_MUSIC_WATCHDOG_MS` | `480` | 끝 구간 진입 후 짧은 지연 뒤 한 번 더 확인해, 여전히 끝 근처면 강제로 다음 트랙으로 진행(`watchdog`). |
| `BG_MUSIC_ADVANCE_DEBOUNCE_MS` | `420` | 연속된 `advance` 호출(이벤트 폭주)을 막기 위한 최소 간격. |
| `BG_MUSIC_ERROR_SUPPRESS_MS` | `400` | 새 트랙을 `load`할 때마다 짧은 구간은 `error` 이벤트로 인한 즉시 스킵을 무시(전환 직후 오탐 완화). |

## 3. 런타임 구조: ref·state 동기화

### 3.1 Ref 목록 (오디오·BGM 전용)

이벤트 리스너와 `setInterval`/`setTimeout` 콜백이 **항상 최신 조건**을 읽도록, “진실 소스”는 ref에 미러링한다.

| Ref | 역할 |
|-----|------|
| `audioRef` | `new Audio()`로 만든 단일 `HTMLAudioElement`. 앱 전체에서 BGM은 이 인스턴스 하나. |
| `fadeIntervalRef` | `fadeAudio`용 `setInterval` ID. 새 트랙 시작 시 기존 페이드를 취소한다. |
| `simulationActiveRef` | `simulation.isActive` 미러. effect보다 먼저 true로 세우는 코드 경로가 있어(아래 7절) 중요. |
| `musicOnRef` | `musicOn` 미러. |
| `pendingAudioPauseRef` | “페이드아웃 후 pause 예정” 플래그. 이 동안은 advance·visibility 재생 시도를 막는다. |
| `lastMusicTrackRef` | 직전에 재생(또는 시도)한 트랙 URL. 연속 동일 곡 완화에 사용. |
| `musicRetryTokenRef` | `play()` 실패 시 재시도할 때, 오래된 `catch` 콜백이 새 재생을 덮어쓰지 않게 하는 토큰. |
| `bgMusicLastAdvanceMsRef` | debounce용 마지막 advance 시각. |
| `bgMusicWatchdogTimerRef` | 끝 구간 워치독 `setTimeout` ID. |
| `bgMusicSuppressErrorAdvanceUntilRef` | 이 시각 이전에는 `error`로 advance하지 않음. |
| `maybeAdvanceBackgroundMusicRef` | `useEffect` 안에서 등록하는 리스너가 클로저 stale을 피하도록 최신 함수를 가리킴. |
| `onVisibilityForBgMusicRef` | `visibilitychange` 핸들러가 최신 로직을 호출하도록. |

### 3.2 State

- `musicOn`: `useState(true)` — 기본은 음악 켜짐.
- `simulation.isActive`: 주행 활성 여부(시뮬레이션 객체의 일부).

### 3.3 ref 동기화 effect

- `simulation.isActive`가 바뀔 때마다 `simulationActiveRef.current` 갱신.
- `musicOn`이 바뀔 때마다 `musicOnRef.current` 갱신.

## 4. 오디오 엘리먼트 생명주기

### 4.1 마운트 시 1회 effect (`[]`)

1. `audioRef.current`가 없으면 `new Audio()` 생성.
2. 리스너 등록:
   - **`ended`:** 워치독 클리어 후 `maybeAdvanceBackgroundMusic('ended')`.
   - **`error`:** 억제 구간이 지났을 때만 워치독 클리어 후 `maybeAdvanceBackgroundMusic('error')`.
   - **`timeupdate`:** 아래 [5.3절](#53-timeupdate--워치독) 참고.
3. 언마운트 시: 리스너 제거, `pause()`, `audioRef = null`, 페이드 interval 정리.

DOM에 `<audio>` 태그를 두지 않고 **숨은 Audio 객체만** 사용한다.

### 4.2 `visibilitychange` effect (`[]`)

- `document.visibilityState === 'visible'`일 때 `onVisibilityForBgMusicRef.current()` 호출.
- 백그라운드에서 돌아왔을 때 **끝난 것처럼 보이거나** 끝 근처인데 멈춘 경우를 복구한다([6절](#6-visibility-복구-onvisibilityforbgmusicref)).

## 5. 핵심 함수 흐름

### 5.1 `fadeAudio(targetVolume, duration?, onComplete?)`

- 50ms 간격으로 `audio.volume`을 선형 보간해 `targetVolume`까지 변경(기본 duration 2000ms).
- 새 페이드 시작 시 기존 interval을 정리한다.
- BGM 시작 시: `startMusicTrack`에서 볼륨 0으로 둔 뒤 **`fadeAudio(0.3)`**으로 서서히 0.3까지 올린다(약 2초).
- 정지 시: **`fadeAudio(0, 2000, onComplete)`**로 서서히 음소거 후 콜백에서 `pause` 여부 결정([8절](#8-주행음악-off-페이드아웃--pendingaudiopauseref)).

### 5.2 `pickRandomTrack(exclude?)`

- 플레이리스트가 비면 `null`.
- 한 곡뿐이면 그 URL 반환.
- 그 외: 최대 6번 랜덤 추출해 `exclude`와 다른 곡을 고른다(직전 곡과의 즉시 반복 완화).
- 6번 모두 같으면 `PLAYLIST`에서 `exclude`의 다음 인덱스로 순환(fallback).

### 5.3 `startMusicTrack(track, token)`

1. 워치독 타이머가 있으면 취소.
2. `bgMusicSuppressErrorAdvanceUntilRef`를 `now + BG_MUSIC_ERROR_SUPPRESS_MS`로 설정(곧 이어지는 `load`/`error` 억제).
3. 진행 중 페이드 interval 취소, `pendingAudioPauseRef = false`(새 재생이 pause 시퀀스와 충돌하지 않게).
4. `pause()` → `src = track` → `load()` → `currentTime = 0` (실패는 무시). **같은 URL이라도** `currentTime` 리셋으로 “ended에 묶인” WebView 상태를 풀려는 의도.
5. `volume = 0` 후 `audio.play()` → Promise `catch` 시:
   - 토큰 불일치면 무시(더 새로운 `startMusicTrack`이 있음).
   - 주행 비활성 또는 음악 OFF면 무시.
   - 다른 랜덤 트랙을 고른 뒤 250ms 후 같은 토큰이면 `startMusicTrack(next, token)` 재귀(자동재생 차단·일시 실패 완화).
6. 성공 경로에서 `fadeAudio(0.3)`.

### 5.4 `playRandomMusic()`

- `pickRandomTrack(lastMusicTrackRef.current)`로 URL 선택 → `lastMusicTrackRef` 갱신 → `musicRetryTokenRef` 증가 → `startMusicTrack(track, token)`.

### 5.5 `maybeAdvanceBackgroundMusic(reason)`

진입 조건을 모두 만족할 때만 `playRandomMusic()` 호출:

- `simulationActiveRef.current && musicOnRef.current`
- `!pendingAudioPauseRef.current`
- `Date.now() - bgMusicLastAdvanceMsRef.current >= BG_MUSIC_ADVANCE_DEBOUNCE_MS`

`reason`이 `'error'`이면 콘솔에 `[BgMusic] advance after error` 경고.

### 5.6 `timeupdate` + 워치독

조건: 주행 활성 + 음악 ON + pause 예정 아님. `ended`면 워치독만 정리하고 return.

- `duration`이 유효하지 않으면 return.
- `currentTime < duration - BG_MUSIC_NEAR_END_SEC`이면 **끝 구간이 아님** → 워치독 타이머 취소 후 return.
- 이미 끝 구간이면:
  - 동일 `src`에 대해 워치독이 아직 없을 때만 `BG_MUSIC_WATCHDOG_MS` 후 콜백 스케줄.
  - 콜백에서 `audio`가 바뀌었거나(`src` 불일치) 조건이 깨졌으면 무시.
  - 여전히 끝 근처(`ended` 또는 `currentTime >= d2 - BG_MUSIC_NEAR_END_SEC * 0.85`)이면 `maybeAdvanceBackgroundMusic('watchdog')`.

즉, **`ended`만 믿지 않고** “끝 근처에서 한동안 멈춤”을 워치독으로 다음 곡 전환에 연결한다.

## 6. Visibility 복구 (`onVisibilityForBgMusicRef`)

`document.visibilityState === 'visible'`일 때만 동작.

1. 주행·음악·pause 예정이 아니어야 함.
2. `audio.ended`면 `maybeAdvanceBackgroundMusic('visibility')`.
3. `duration`이 유효하고 `currentTime >= duration - BG_MUSIC_NEAR_END_SEC`이면 역시 advance(탭 복귀 시 끝 구간에서 멈춘 경우).
4. `audio.paused`이면 `play()` 시도:
   - 실패 시(`catch`), 여전히 주행+음악+pause 예정 아니고, `ended` 또는 끝 근처면 `maybeAdvanceBackgroundMusic('visibility')` (재생 재개 실패 = 사실상 끝으로 간주해 다음 곡).

## 7. 주행 시작과 ref 선반영

`startSimulationCore`(주행 시작 핵심)에서 `setSimulation({ isActive: true, ... })` **이전에** 다음을 실행한다:

```ts
simulationActiveRef.current = true;
```

의도: 코칭·음악 등 **ref 기반 로직이 React effect flush를 기다리지 않고** 즉시 “주행 중”으로 동작하게 한다. BGM 직접 호출은 아니지만, `play()` 실패 `catch`나 다른 비동기 콜백에서 `simulationActiveRef`를 읽을 때 레이스를 줄인다.

## 8. 주행/음악 OFF: 페이드아웃 + `pendingAudioPauseRef`

`useEffect` 의존성: `[simulation.isActive, musicOn]`.

### 8.1 켜는 경우: `simulation.isActive && musicOn`

- `audioRef`가 있고 (`paused` **또는** `pendingAudioPauseRef`)이면 `playRandomMusic()`.
- 일시정지에서 재개했을 때 페이드아웃으로 멈춘 뒤 `pendingAudioPauseRef`만 남은 경우에도 다시 랜덤 트랙으로 시작한다.

### 8.2 끄는 경우: 위 조건이 false

- 재생 중(`!paused`)일 때만:
  1. `pendingAudioPauseRef = true`
  2. `fadeAudio(0, 2000, () => { ... })`
  3. 콜백에서 `simulationActiveRef.current && musicOnRef.current`가 다시 true면 **`playRandomMusic()`** 후 return (페이드 도중 사용자가 다시 켠 경우).
  4. 그렇지 않으면 `pause()`, `pendingAudioPauseRef = false`.

정리: **시뮬 정지·일시정지·음악 뮤트** 모두 “조건 false”로 묶여 2초 페이드아웃 후 정지한다. `pendingAudioPauseRef`로 그 사이 `advance`/`visibility`가 다음 곡을 잘못 띄우는 것을 막는다.

## 10. 시나리오별 동작 요약

| 시나리오 | 동작 |
|----------|------|
| 주행 시작(Go 등) + 음악 ON | effect 또는 재개 조건에서 `playRandomMusic` → 페이드 인. |
| 주행 일시정지(Pause) 또는 Stop | `isActive` false → 페이드아웃 후 pause. |
| 주행 중 음악만 OFF | `musicOn` false → 동일하게 페이드아웃. |
| 트랙 정상 종료 | `ended` → 다음 곡. |
| 트랙 끝에서 멈춤·`ended` 없음 | `timeupdate`가 끝 구간 감지 → 워치독 → `watchdog` advance. |
| 네트워크/디코딩 오류 | 억제 시간 이후 `error` → advance. |
| 탭 백그라운드 후 복귀 | `visibility` 핸들러로 끝/끝 근처/재생 실패 처리. |
| `play()` 거부(자동재생 정책 등) | 다른 트랙으로 지연 재시도(동일 토큰·주행·음악 유지 시). |

## 12. 한계·주의사항

- **저작권·호스팅:** 트랙은 Dropbox URL에 직접 의존한다. 링크 만료·정책 변경 시 재생 실패 가능.
- **동시 재생:** 단일 `Audio` 인스턴스이므로 BGM은 항상 한 곡만 재생된다.
- **코칭과의 믹스:** Web Speech API / 네이티브 TTS와의 볼륨 밸런스는 BGM만 0.3 상한으로 제한되어 있고, 별도 덕킹(ducking) 로직은 이 문서 범위의 BGM 블록에는 없다.
- **빌드 산출물:** BGM은 순수 클라이언트 로직이며, Vite 빌드에 별도 오디오 에셋을 포함하지 않는다(원격 URL 스트리밍).
