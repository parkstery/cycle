## 2. 현재 기술 스택 (실제 코드 기준)

### 2.1 프론트엔드

| 구분 | 기술 | 비고 |
|------|------|------|
| **프레임워크** | React 18.2 + TypeScript | 함수형 컴포넌트, Hooks |
| **빌드** | Vite 5 | ESM, HMR |

| **지도** | **Leaflet 1.9 + OSM** | Google Maps 아님 — OpenStreetMap 타일 |

### 2.2 외부 서비스 (실제 사용)

| 용도 | 서비스 | 비고 |
|------|--------|------|
| **경로(라우팅)** | **OSRM** (`router.project-osrm.org`) | cycling / foot 프로필, Google Directions 미사용 |
| **지오코딩** | **Nominatim** (OSM) | 주소↔좌표, Plus Code 지원 (`plusCode.ts`) |
| **고도** | **Open Elevation API** | 경로 샘플 100개 POST 조회 |
| **Street View** | **Google Maps API** | StreetViewPanorama, StreetViewService만 사용 |
| **AI 코칭** | **로컬 로직 + phraseManifest** | Gemini API 미사용 — 경사→저항 매핑 + 미리 녹음/문구 |

### 2.3 배포·PWA

- **Vercel**: `vercel.json` SPA rewrites
- **PWA**: `manifest.json`, `public/sw.js` (현재 index.html에서 매 로드 시 SW 해제·캐시 삭제)
- **진입점**: `index.tsx` → `main.css`, `App.tsx`

## 3. 코드 구조 요약

### 3.1 파일 구성

```
cycle/
├── App.tsx              # 메인 앱 (~1,132줄) — 지도·경로·시뮬·SV·코칭·UI 일체
├── ElevationChartView.tsx  # 고도 차트 (Recharts, ReferenceLine)
├── index.tsx, main.css, index.html
├── types.ts             # RouteInfo, ElevationPoint, SimulationState, CoachingData, SavedRoute, PanoDataItem 등
├── services/
│   ├── aiCoach.ts       # getAdvancedCoaching, getPredictiveCoaching, getCourseBriefing, getRideEncouragement (로컬)
│   ├── nominatim.ts     # 역지오코딩, 주소→좌표, Plus Code 처리
│   ├── openElevation.ts # 경로 고도 샘플 조회
│   ├── geoUtils.ts      # decodePath, computeDistanceBetween, computeHeading, computeOffset
│   ├── phraseManifest.ts# 코칭 문구 (tip_0..31, res_1..8)
│   └── plusCode.ts      # Plus Code 디코딩
├── public/              # 스트리트뷰 아이콘, sw.js, 코칭 음원 등
└── Report/              # 문서
```

### 3.2 App.tsx 역할 (단일 파일 비대)

- **지도**: Leaflet 초기화, OSM 타일, 클릭 시 Nominatim 역지오코딩 → 출발/도착/경유지 설정
- **경로**: OSRM 호출 → 폴리라인 디코딩 → 2m 밀도 보간 → Open Elevation으로 고도 → 경사 기반 주행 시간 계산
- **Street View**: 더블 버퍼(panorama1/2), GOOGLE → DEFAULT 폴백, 전진만 허용(pathIndex), Progressive 로딩(초기 200m + 온디맨드 세그먼트)
- **시뮬레이션**: 속도(km/h) 기반 인덱스 진행, 60km/h 상한으로 SV 전환, 80km/h 초과 시 20m 단위 점프
- **AI 코칭**: 경사→저항(1~8) → phraseManifest 문구 + TTS(speak), 예측 코칭(cachedCoaching) + 21스텝 레거시
- **UX**: 검색(Nominatim), 즐겨찾기(내 경로 5개), 배경 음악(드롭박스), 카운트다운(Go 시 3-2-1-Start!), 접이식 패널

### 3.3 타입 정의 (types.ts)

- `RouteInfo`: path, elevation, panoData, cachedCoaching 포함
- `AppPhase`: 'IDLE' | 'PREPARING' | 'RUNNING' (API 허용 구간 제어)
- `PanoDataItem`, `CachedCoachingItem`: 전처리/캐시 구조
- `CoachingData`, `SavedRoute` 등 일관되게 사용됨

## 7. 코드 품질 요약

### 7.1 강점

- 타입 정의가 `types.ts`에 명확히 있음.
- 지도/라우팅/고도/코칭이 서비스 레이어로 분리됨 (`nominatim`, `openElevation`, `geoUtils`, `aiCoach`).
- Ref로 Leaflet·Street View 인스턴스 보관해 불필요 리렌더 완화.
- 경로 재사용 로직(`inputsMatch`, `lastRouteRequestRef`)으로 동일 입력 시 재계산 방지.

### 7.2 개선 권장

| 항목 | 내용 |
|------|------|
| **단일 파일 비대** | `App.tsx` 약 1,132줄 — Map / Simulation / StreetView / Panels 단위로 컴포넌트·훅 분리 시 가독성·테스트 용이 |
| **전역 타입** | `declare var google: any` — Street View만 사용하더라도 `@types/google.maps` 도입 시 타입 안정성 향상 |
| **문서 정합성** | DEVELOPMENT_STATUS_REPORT.md를 OSRM/Nominatim/Open Elevation/로컬 코칭 기준으로 수정 권장 |
| **index.css** | `index.html`은 `main.css`를 참조하지 않음. 진입점은 `index.tsx`에서 `main.css` import — 정리됨. |
