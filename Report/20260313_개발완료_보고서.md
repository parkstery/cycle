# Cycle Simulator 개발 완료 보고서

**작성일:** 2026년 3월 13일  
**프로젝트명:** Fitness Pro Mobile GIS / Cycle Simulator (Ride the World - Indoor Cycling)  
**문서 유형:** 개발 완료 보고서

---

## 1. 개요

본 문서는 **Cycle Simulator** 프로젝트의 **개발 완료**를 정리한 보고서이다. 자전거·도보 경로 시뮬레이션, 거리뷰(Street View) 연동 주행, 고도 기반 AI 코칭, 경로 탐색·장소 검색을 제공하는 **PWA·모바일 GIS 애플리케이션**으로, 웹 배포 및 Android 네이티브 빌드(Capacitor)까지 적용된 최종 산출물을 기준으로 서술한다.

## 3. 완료된 핵심 기능

### 3.1 지도 및 경로 (WEB GIS)

| 기능 | 완료 내용 |
|------|-----------|
| 지도 표시 | Google Maps 베이스맵(roadmap/hybrid), 줌/풀스크린, 클릭 시 위치 정보 표시 |
| 장소 검색 | Nominatim 검색, 최근 검색 5건 저장, 검색 결과 지도 중심·마커 반영 |
| 출발/도착/경유 | 텍스트 입력 또는 지도 클릭으로 A/B/경유(최대 3개) 설정, 출발·도착 스왑 |
| 경로 탐색 | OSRM(cycling/foot) 경로 계산, 2m 밀도 보간, 폴리라인·마커·거리·이동 시간 표시(경사 반영) |
| 고도 데이터 | Open-Elevation API로 경로 상 100샘플 고도 조회, 경로별 캐시 |
| 고도 프로필 차트 | Recharts AreaChart, 시뮬레이션 중 현재 위치 참조선(ReferenceLine) 동기화 |

### 3.2 거리뷰(Street View)

| 기능 | 완료 내용 |
|------|-----------|
| 주행 연동 | 경로 방향 기준 파노라마 표시, GOOGLE → DEFAULT(사용자 제작) 폴백 |
| 품질·연속성 | 더블 버퍼·점진적 로딩(초기 200m→300m, 10m 간격), 슬라이딩 400m prefetch |
| 선로딩·캐시 | PREPARING 시 선로딩, RUNNING 중 주행 중 실시간 getPanorama 제거(Phase 1), 캐시 우선 |
| 품질 필터 | 실내 파노 필터(description), coverage 70% 미만 시 안내 배지 |
| UI | 풀스크린/미니맵 토글, 거리뷰 커버리지 레이어 토글 |

### 3.3 주행 시뮬레이션

| 기능 | 완료 내용 |
|------|-----------|
| 재생 제어 | 재생/일시정지/정지, 속도 10~100 km/h 설정 |
| 진행 표시 | 경로 방향 마커, 경과 시간·주행 거리, 고도 차트 커서 동기화 |
| 완주 처리 | 경로 완주 시 자동 정지 및 TTS 완주 메시지 |
| Go·카운트다운 | 경로 탐색 후 Go 클릭 시 3→2→1→Start! 카운트다운 후 시뮬 자동 시작, 동일 입력 시 경로 재요청 없이 시뮬만 시작 |

### 3.4 AI 코칭

| 기능 | 완료 내용 |
|------|-----------|
| 코칭 로직 | 경사도→저항 밴드 규칙 + phraseManifest 기반 멘트, 예측 코칭(cachedCoaching)·21스텝 주기 |
| TTS | 브라우저 Speech Synthesis, 코칭/시작·종료 멘트(getCourseBriefing, getRideEncouragement) |
| 비용·오프라인 | Gemini API 미사용, 로컬 규칙 + phraseManifest + TTS로 무료·오프라인 대응 |
| UX | 코칭/배경음 온오프 토글 |

### 3.5 부가 기능

| 기능 | 완료 내용 |
|------|-----------|
| 즐겨찾기(My Routes) | 현재 경로 최대 5개 저장·로드·삭제, localStorage |
| 배경 음악 | 시뮬 중 Dropbox MP3 플레이리스트 랜덤 재생, 페이드 인/아웃 |
| 교통 레이어 | Google Traffic Layer 토글 |
| 반응형 UI | 접이식 검색/경로 입력/고도/히스토리 패널, 풀스크린 대응 |

## 4. 기술 스택 및 아키텍처

### 4.1 기술 스택

| 구분 | 기술 | 비고 |
|------|------|------|
| 언어 | TypeScript | 5.2.x |
| 프레임워크 | React | 18.2.x, 함수형 컴포넌트·Hooks |
| 빌드 | Vite | 5.x, @vitejs/plugin-react |
| 스타일 | Tailwind CSS | 3.3.x, PostCSS, Autoprefixer |
| 차트 | Recharts | 2.10.x (고도 프로필) |
| 아이콘 | Lucide React | 0.294.x |
| 지도·거리뷰 | Google Maps JavaScript API | 동적 스크립트 로드, Street View 포함 |
| 배포 | Vercel | 정적 SPA + Serverless API |
| 모바일 | Capacitor | 8.2.x, Android 빌드 지원 (appId: com.liveonsoft.cycle) |
| PWA | manifest.json, Service Worker | 테마·오프라인 대응 |

### 4.2 외부 서비스·비용 정책

| 용도 | 사용 서비스 | 비고 |
|------|-------------|------|
| 경로 탐색 | OSRM (Vercel API 프록시) | Google Directions 대신 사용 |
| 지오코딩·검색 | Nominatim (Vercel API 프록시) | Google Geocoder 대신 사용 |
| 고도 | Open-Elevation API | Google Elevation 대신 사용, 경로당 1회 POST·캐시 |
| AI 코칭 | 로컬 규칙 + phraseManifest + TTS | Gemini 미사용 |
| 지도·거리뷰 | Google Maps JS · Street View | Google API 사용 구간으로 한정 |

Google 의존도는 **지도·Street View에 한정**되며, 경로·지오코딩·고도·코칭은 오픈소스·로컬 처리로 구성되어 있다.

## 7. 알려진 제한 사항 및 권장 사항

### 7.1 제한 사항

- **실시간 위치 추적**: 실제 GPS 기반 실시간 추적은 미구현, 시뮬레이션 모드만 지원.
- **단일 파일 규모**: App.tsx가 1,800줄 이상으로 비대하여, 추후 컴포넌트·훅 분리 시 유지보수성 향상 가능.
- **Google 타입**: `declare var google: any` 사용, `@types/google.maps` 도입 시 타입 안정성·자동완성 개선 가능.

### 7.2 권장 사항 (우선순위)

1. **필수**: `.env.example` 추가 및 README에 API 키·환경 변수 설정 방법 명시.
2. **권장**: App.tsx를 Map / Simulation / StreetView / Panels 등으로 분리하고, useMap, useSimulation, useStreetView 등 훅으로 로직 추출.
3. **권장**: `@types/google.maps` 추가로 `google` 객체 타입 정리.
4. **선택**: Bottom Sheet 전용 컴포넌트·실시간 Geolocation 추적 등 로드맵 항목의 진행 여부 및 일정 결정.
