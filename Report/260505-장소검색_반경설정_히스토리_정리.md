# 장소 검색 반경 설정 히스토리 정리

작성일: 2026-05-05  
대상 코드: `App.tsx`, `services/nominatim.ts`, `services/osrmRoute.ts`

## 1. 요약

이 프로젝트의 "장소 검색"은 실제로 3개 층으로 동작하며, 반경/범위 처리 방식도 서로 다릅니다.

1) **텍스트 자동완성 검색**(출발/도착/상단 검색창)  
- Nominatim `searchSuggestions()` 기반  
- **반경 파라미터 없음** (문자열 검색 + `limit`)  

2) **좌표 -> 주소 변환(맵 클릭/경로 클릭)**  
- Nominatim `reverse()` 기반  
- 직접 `radius`는 없고, **주변 오프셋 탐색 + zoom 단계 하향**으로 범위를 넓히는 방식  

3) **주소/좌표 -> 경로 계산(OSRM 스냅)**  
- `radiuses` 파라미터 사용  
- 현재: **100m strict -> NoSegment면 300m fallback**

즉, 사용자가 체감하는 "검색 반경"은 단일 값이 아니라, 위 3개 계층에서 각각 다르게 설계되어 있습니다.

## 2. 현재 코드 기준 상세

## 2.1 텍스트 자동완성(반경 없음)

`App.tsx`:
- 출발지: `nominatim.searchSuggestions(q, 5)`
- 도착지: `nominatim.searchSuggestions(q, 5)`
- 상단 장소검색: `nominatim.searchSuggestions(q, PLACE_SEARCH_SUGGEST_LIMIT)` (`PLACE_SEARCH_SUGGEST_LIMIT = 8`)
- 디바운스: 상단 `350ms`, 출발/도착은 즉시 타이머(0ms) + 요청 ID 가드

`services/nominatim.ts`:
- `searchSuggestions(query, limit)` -> Nominatim `/search?...&limit=...`
- `MIN_INTERVAL_MS = 1100` 쓰로틀로 요청 빈도 제한
- 캐시 키: `query + limit`

정리:
- 자동완성은 "반경 기반 근접 검색"이 아니라 "문자열 매칭 기반 후보 제한(limit)" 구조입니다.

## 2.2 좌표 기반 주소 결정(오프셋 + zoom 하향)

`App.tsx` `resolveNearestAddress()`:
- 1차: 중심 좌표 `reverse(lat,lng)` 직접 조회
- 2차: 주변 오프셋 다단계 조회  
  - 대략 ±0.00035, ±0.00075, ±0.0015, ±0.003, ±0.005 (위경도)  
  - 주석상 약 40m~700m 탐색 의도
- 3차(최후 보정): 동일 좌표에서 `zoom`을 16 -> 14 -> 12 -> 10 -> 8 -> 6 순으로 낮춰 재조회

정리:
- 여기서는 `radius` 필드를 쓰지 않고, **공간 오프셋 + 행정단위 확대(zoom 하향)**로 "가까운 유효 주소"를 확보합니다.

## 2.3 경로 스냅 반경(OSRM radiuses)

`services/osrmRoute.ts`:
- `OSRM_SNAP_RADIUS_STRICT_M = 100`
- `OSRM_SNAP_RADIUS_RELAXED_M = 300`
- 흐름: strict(100m) -> 결과가 `NoSegment`면 relaxed(300m) 1회 재시도
- 결과 메타: `_meta.osrmSnapRadiusM`, `_meta.osrmSnapRelaxed`

`App.tsx`:
- 완화 재시도 성공 시 사용자 안내(alert) 표시  
  ("100m 내 도로 없음 -> 300m로 확대해 경로를 찾았다")

정리:
- 실제 "반경 설정값"이 명시적으로 존재하는 계층은 현재 OSRM 스냅 계층입니다.

## 4. 해석 포인트 (왜 "반경"이 헷갈리는가)

사용자 관점에서는 모두 "장소 찾기"로 보이지만, 실제로는:

- 자동완성: `limit` 중심(문자열 기반)
- 맵 클릭 주소화: 오프셋/zoom 중심(공간 근접 보정)
- 경로 계산: `radiuses` 중심(OSRM 스냅 반경)

따라서 "검색 반경이 커졌다/작아졌다"는 체감은 보통 2번(주소 보정) 또는 3번(OSRM 스냅)의 영향이며,  
1번 자동완성은 반경이 아니라 후보 개수/디바운스/쓰로틀의 영향을 받습니다.
