# 경로 주행 중 My Routes 선택 후 거리뷰 멈춤 — 원인 및 해결방안

## 현상
- 현재 경로 주행 도중, My Routes에서 다른 경로를 선택하고 주행(Go) 버튼을 누르면:
  - **맵**: 선택한 경로로 정상 전환되고, 주행 중인 것처럼 표시됨.
  - **거리뷰**: 이전 경로의 거리뷰 위치에서 멈춘 채로 오래 유지됨.

---

## 원인 분석

### 1. 경로 전환 시 시퀀스와 상태 불일치

- Go 버튼 동작:  
  입력(출발/도착/웨이포인트)이 **마지막으로 탐색한 경로와 다르면** `calculateRoute(mode, true)` 호출 → **새 경로 탐색 + autoStart**.
- 흐름 요약:
  1. OSRM·표고 조회 후 **먼저** `setRoute({ path: densifiedPath, elevation, ... })` 호출 → **맵/폴리라인과 route 상태는 즉시 새 경로로 갱신**.
  2. **거리뷰용 panoData**는 별도 비동기 `preFetchStreetViewData(...)` 안에서만 채워지고, 완료 후 `setRoute(prev => ({ ...prev, panoData }))` 로 한 번 더 갱신됨.
- 따라서 **일정 구간** 동안은 “경로(path)만 새 경로, panoData는 아직 없거나 이전 경로 것”인 상태가 됨.

### 2. 시뮬레이션은 새 path 기준으로만 동작

- 시뮬레이션 이펙트는 `route.path`와 `simulation.currentIndex`만 사용.
- **새 path가 설정된 직후**:
  - `simulation.currentIndex`는 **이전 경로 주행 중이던 값**(예: 5000) 그대로임.
  - 새 경로 path 길이가 **이전 currentIndex보다 크면** (예: 새 path.length = 8000):
    - `currentIdx >= route.path.length - 1` 조건이 false → **시뮬레이션은 종료되지 않고 그대로 진행**.
  - 이때 **route.panoData**는:
    - 아직 비동기 prefetch 미완료면 **undefined** 또는 **이전 경로의 panoData**가 남아 있을 수 있음.
- 거리뷰 갱신 로직은 `route.panoData`와 `svDisplayPathIndexRef`를 사용해 `getPanoDataForIndex(route.panoData, svDisplayIdxForPano)`로 표시할 파노를 고름.
- 따라서:
  - **panoData가 새 경로 것으로 갱신되기 전**에는 이전 경로의 파노라마가 계속 사용되거나,
  - **panoData가 비어 있으면** `route.panoData?.length`가 falsy라 경고만 켜지고 **파노라마 뷰는 전혀 갱신되지 않음** → “이전 경로 거리뷰에서 멈춘 것처럼” 보임.

### 3. ref 초기화 시점

- `svDisplayPathIndexRef`, `lastDisplayedPanoPathIndexRef`는 **시뮬레이션 이펙트 안에서만** `currentIdx === 0`일 때 0 / -1로 리셋됨.
- 경로만 바뀌고 **시뮬레이션은 종료되지 않고** currentIndex가 0이 아닌 채로 진행되는 경우, 이 ref들은 **이전 경로 기준 큰 값**을 유지.
- 새 경로의 panoData가 나와도 “이미 지나간 pathIndex”로 해석되거나, 새 panoData와 인덱스 체계가 맞지 않아 **갱신이 한동안 또는 계속 일어나지 않을 수 있음**.

### 4. autoStart 시에도 지연 가능

- autoStart 시에는 prefetch 완료 후 `setRoute(..., panoData)` → 카운트다운 → `countdownDoneRef()`에서 **새 경로의 첫 파노**로 `setPanoramaViewByPanoId(firstPano)` 호출.
- 다만 **preFetchStreetViewData(300m, 10m 간격)** 가 끝날 때까지는:
  - 맵은 이미 새 경로,
  - 시뮬레이션은 위와 같이 “새 path + 옛 currentIndex”로 돌 수 있고,
  - 거리뷰는 **panoData 미갱신** 때문에 이전 위치에 머무름 → 사용자 체감상 “장시간 멈춤”.

### 5. 요약 원인

| 원인 | 설명 |
|------|------|
| **path와 panoData 갱신 시점 분리** | path는 즉시, panoData는 비동기 prefetch 완료 후에만 반영되어, 그 사이 구간에서 거리뷰는 이전 경로/빈 데이터 기준으로 동작. |
| **경로 전환 시 시뮬레이션/ref 미리셋** | route가 새 path로 바뀌어도 `currentIndex`와 거리뷰용 ref를 경로 전환 시점에 초기화하지 않아, 새 경로와 인덱스가 어긋남. |
| **경로 전환 시 거리뷰 뷰 미갱신** | “경로만 바뀐 상태”에서 한 번도 새 경로의 시작점(또는 현재 위치)으로 파노라마를 강제로 설정하지 않음. |

## 해결방안 (구현 없이 제안만)

### 방안 1: 경로 교체 시 시뮬레이션·거리뷰 상태 일괄 리셋 (권장)

- **경로를 새 path로 설정하는 모든 지점**(예: `calculateRoute` 내부에서 `setRoute({ path, ... })` 호출하는 곳)에서:
  - **동시에** `setSimulation({ isActive: false, currentIndex: 0, speed: ... })` 로 시뮬레이션 중단 및 인덱스 0으로 초기화.
  - `svDisplayPathIndexRef.current = 0`, `lastDisplayedPanoPathIndexRef.current = -1` 등 거리뷰용 ref도 0/시작값으로 초기화.
- 효과: “경로만 바꾸고 주행은 옛 인덱스로 계속”하는 상황을 제거하고, 새 경로는 항상 0번 인덱스부터 시작.

### 방안 2: 경로 교체 직후 거리뷰를 “끄거나” 초기 위치로 고정

- 새 path를 설정한 직후, **panoData가 아직 없어도**:
  - 옵션 A: 거리뷰 컨테이너를 일시 숨기거나 “경로 불러오는 중” 메시지 표시.
  - 옵션 B: 새 경로의 **시작점 좌표 + heading**만으로 `setPanoramaView(startPos, heading)` 호출(API 폴백 사용)해, 최소한 “이전 경로의 마지막 파노”가 아닌 “새 경로 시작점”으로 화면을 옮김.
- panoData prefetch가 끝나면 기존대로 `panoData[0]`으로 한 번 더 설정해도 됨.

### 방안 3: panoData가 준비될 때까지 시뮬레이션 시작 지연

- autoStart일 때:
  - **preFetchStreetViewData가 완료된 뒤**에만 `setRoute(..., panoData)` 와 카운트다운/`countdownDoneRef()`(첫 파노 설정)를 실행하는 현재 구조는 유지.
  - 대신 **path만 설정한 직후**에는 반드시 **시뮬레이션을 중단**해 두고(`setSimulation(..., isActive: false)`), “주행 진행”은 prefetch + 카운트다운이 끝난 뒤에만 시작되도록 함.
- 이렇게 하면 “맵은 새 경로인데 시뮬레이션은 옛 인덱스로 움직이는” 구간이 없어져, 거리뷰와 경로가 어긋난 채 멈춰 보이는 현상을 줄일 수 있음.

### 방안 4: route 변경 시 “경로 ID/버전”으로 구분

- route에 `routeId` 또는 `routeVersion`을 두고, **route가 바뀔 때마다** 시뮬레이션 이펙트나 거리뷰 로직에서 “이전에 쓰던 route와 다른가?”를 비교.
- 다르면 **현재 표시 중인 파노라마와 ref를 버리고**, 새 경로의 시작점으로 한 번 초기화한 뒤에만 인덱스 진행을 허용.
- ref 초기화와 “첫 파노 설정”을 **route 변경 감지**와 묶어서 한 곳에서만 하면, 경로 전환 경로(My Routes 선택 후 Go, 또는 재탐색)가 여러 개여도 동일하게 동작하게 할 수 있음.

### 방안 5: My Routes 선택 시 동작 정책 명확화

- My Routes에서 경로를 선택했을 때:
  - **즉시 경로 탐색(autoStart 여부와 무관)** 이라면: 경로 전환 시 위 1·2·3을 적용해 “경로 바뀌면 무조건 시뮬레이션·거리뷰 리셋 후 시작”으로 통일.
  - **선택만 하고 Go를 눌렀을 때만 탐색**이라면: Go에서 `calculateRoute(mode, true)` 호출 후, **path가 설정되는 시점**에 위 1번(리셋)을 적용하고, prefetch 완료 후에만 주행/거리뷰 시작(3번)과 결합하면 됨.

## 권장 조합

- **반드시 적용 권장**: **방안 1** — 새 path를 넣는 모든 `setRoute` 직후에 시뮬레이션 중단 + currentIndex 0 + 거리뷰 ref 초기화.
- **체감 개선 추가**: **방안 2** — path만 바뀐 직후, panoData 유무와 관계없이 새 경로 시작점으로 한 번 `setPanoramaView(startPos, heading)` 호출하거나, “불러오는 중” 표시로 이전 거리뷰에 멈춰 보이는 시간을 줄임.
- **일관성 강화**: **방안 3** — path만 설정된 동안에는 시뮬레이션을 절대 진행하지 않도록 하고, prefetch + 카운트다운 후에만 `isActive: true`로 전환.

이렇게 하면 “주행 중 My Routes 선택 후 Go” 시 맵과 거리뷰가 모두 새 경로 기준으로 맞춰지고, 이전 경로 거리뷰에 장시간 멈춰 있는 현상을 제거할 수 있습니다.
