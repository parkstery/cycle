# Gemini 활용 검토 — 전환 방침 유지 + 서비스 질 향상을 위한 활용안

**작성일:** 2025-01-31  
**전제:** TTS는 Cache MP3로 전환 유지. Gemini는 단순 TTS 용도로 쓰지 않음.

---

## 1. 전환 방침 재확인

- **Gemini를 단순 TTS 용도로 사용하는 것은 불필요**하며, 사용자 증가 시 **비용 증가 위험**이 있음.
- **현재 MP3 cache로 전환하는 것은 적절한 대안**으로 판단함.
- **이 전환 방침은 유지**함:  
  코칭 음성 출력은 **Cache TTS(phraseManifest + audioCache + services/coaching/*.mp3)** 로만 수행하고, Gemini는 **음성 합성·재생 경로에는 사용하지 않음**.

---

## 2. Gemini 유지 시 활용 가치 — 서비스 질 향상 관점

전환 방침을 유지한 채, **비용 대비 서비스 질 향상**이 기대되는 부분만 Gemini를 유지·활용하는 방안을 정리함.

---

### 2.1 코칭 “선택” 담당 (구조화 출력만, 재생은 Cache TTS)

**역할**  
- 코칭 **문장 생성(자유 텍스트)** 대신, **어떤 캐시 문구를 언제 재생할지**만 Gemini가 결정하도록 제한.
- 예: 입력(경사, 속도, 이전 저항, 구간 특성) → 출력 `{ tipKey: "tip_5", action: "STAND" }` 등 **구조화된 키만** 반환.
- 재생은 **phraseManifest + audioCache**로 기존 Cache TTS 전환안 그대로 사용.

**서비스 질 향상**  
- 지형·속도·이전 저항에 맞춰 **캐시 문구 중 최적 조합**을 고르는 “코칭 선택”을 AI에 맡길 수 있음.
- 자유 텍스트 생성보다 **토큰 사용이 적고**, 출력을 tip_X / res_Y로 고정하면 비용 예측이 쉬움.

**구현 포인트**  
- aiCoach: 프롬프트를 “문장 생성”이 아니라 “tip_0~tip_21 중 하나 + action 선택”으로 변경.
- 응답 스키마: `tipKey`(enum), `action`(enum) 등만 받고, `tip` 자유 문자열은 제거.
- App/재생 경로: Gemini 반환값 `tipKey`·`resKey`(또는 resistance에서 유도) → audioCache.playCoachingThenResistance(tipKey, resKey) 호출.

**비용**  
- 호출 1회당 토큰 소모가 적음(짧은 프롬프트 + 구조화 출력).  
- 기존 “문장 생성 + TTS” 대비 **대폭 감소**, Cache TTS 전환과 함께 유지 가능한 수준으로 조절 가능.

---

### 2.2 주행 전 경로 브리핑 (Pre-ride briefing)

**역할**  
- 경로 확정 후、시뮬레이션 시작 전에, **전체 고도 프로필**을 Gemini에 넘겨 한 번만 호출.
- 출력: 2~3문장 수준의 **경로 요약·전략 조언** (예: “첫 2km 오르막이 힘들어요. 중간 평지에서 회복 후, 마지막 500m 오르막에 대비하세요.”).

**서비스 질 향상**  
- 사용자가 **어디에 힘을 쓸지/아낄지**를 미리 인지할 수 있어, 시뮬레이션 몰입도와 만족도 향상.

**구현 포인트**  
- 입력: 경로 요약(거리, 고도 구간 수, 대표 경사 구간 등).  
- 출력: 자유 텍스트 2~3문장 또는 “브리핑 유형 A/B/C” 등으로 제한 후, UI에 텍스트로 표시.
- 음성: Cache TTS 전환 방침에 따라, (1) 텍스트만 표시하거나, (2) 브리핑용 MP3 1~2종을 두고 유형별로 재생.

**비용**  
- **경로 1회당 1회** 호출. 시뮬레이션 중 코칭 호출보다 빈도가 훨씬 낮음.

---

### 2.3 주행 후 요약·인사이트 (Post-ride summary)

**역할**  
- 시뮬 종료 시, **주행 거리·시간·고도·속도 요약** 등을 Gemini에 넘겨 1회 호출.
- 출력: 2~3문장 수준의 **칭찬·요약·다음 주행 제안** (예: “오르막에서 리듬을 잘 유지했어요. 다음엔 평지 구간 속도를 조금 올려보세요.”).

**서비스 질 향상**  
- “한 번 달렸다로 끝”이 아니라 **피드백과 다음 동기**를 주어 이탈 감소·재이용 증가에 기여.

**구현 포인트**  
- 입력: 거리, 시간, 고도 이득, 평균/구간별 속도 등 (개인 식별 정보 제외).
- 출력: 자유 텍스트 또는 “요약 유형 1~5” 등으로 제한 후 UI에 표시.  
- 음성: 전환 방침 유지 → 텍스트만 표시하거나, 요약용 캐시 문구 1~2종으로 재생.

**비용**  
- **주행 1회당 1회** 호출. 코칭 호출보다 빈도가 낮음.

---

### 2.4 (선택) 자연어 경로 검색·추천

**역할**  
- 사용자 입력 예: “서울 근처 오르막 10km”, “평탄한 강변 코스”.
- Gemini가 **의도·조건**을 해석해, 필터/키워드 또는 짧은 추천 문구로 변환.

**서비스 질 향상**  
- 검색·경로 선택 UX 개선. “어디로 달릴지”를 자연어로 찾을 수 있음.

**비용**  
- 검색 시도당 1회. 사용 패턴에 따라 호출량 변동.  
- 우선순위는 2.1~2.3보다 낮게 두고, 여유 있을 때 도입 검토 가능.

---

## 3. 정리 — Gemini 활용 우선순위

| 순위 | 활용 영역           | 역할 요약                         | 서비스 질 향상           | 비용 특성           |
|------|----------------------|-----------------------------------|---------------------------|----------------------|
| 1    | 코칭 “선택”         | tipKey/resKey 등 구조화 출력만   | 적절한 캐시 문구 선택    | 호출당 토큰 소량     |
| 2    | 주행 전 브리핑      | 경로 1회당 1회, 2~3문장 요약     | 전략적 인지·몰입 향상    | 경로당 1회           |
| 3    | 주행 후 요약·인사이트 | 주행 1회당 1회, 2~3문장 피드백 | 재이용·동기 부여         | 주행당 1회           |
| 4    | (선택) 자연어 검색  | 검색 의도 해석 → 필터/추천       | 경로 발견 UX 개선        | 검색당 1회           |

- **TTS 용도로의 Gemini 사용은 하지 않음** (Cache TTS 전환 유지).
- **서비스 질**을 높이려면:  
  - **1순위:** 코칭은 “문장 생성”이 아니라 “캐시 문구 선택(tipKey/resKey)”만 Gemini에 맡기고, 재생은 전부 Cache TTS.  
  - **2·3순위:** 주행 전 브리핑·주행 후 요약을 텍스트(또는 소수 캐시 문구)로 제공.  
  - **4순위:** 여유 시 자연어 경로 검색·추천 추가.

---

## 4. Cache TTS 전환 실행계획과의 관계

- **execution_plan_cache_tts.md** 의 “TTS → Cache MP3” 전환 및 phraseManifest·audioCache 설계는 **그대로 유지**.
- 위 Gemini 활용안은 **재생 경로를 Cache TTS로 고정한 뒤**,  
  - “무엇을 말할지(tip/res 선택)” 또는  
  - “주행 전/후 어떤 텍스트를 보여줄지”  
  만 Gemini로 보강하는 **추가 레이어**로 두면 됨.
- 구현 시에는 **2.1(코칭 선택)** 을 먼저 반영하고, 2.2·2.3은 단계적으로 도입하는 순서를 권장함.
