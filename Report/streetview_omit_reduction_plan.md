# 거리뷰 생략 감소 방안 (연속 디스플레이 우선)

## 1. 원칙

- **연속적인 거리뷰 디스플레이는 트래픽 증가보다 중요하며 선행되어야 할 가치.**
- 생략되지 않도록 샘플 밀도·폴백·온디맨드 타이밍을 조정.

---

## 2. 현재 코드에서 생략이 발생하는 원인

| 원인 | 설명 |
|------|------|
| **① 샘플 간격 15m** | Street View 파노라마는 도로를 따라 보통 10~20m 간격. 15m면 구간마다 “한 장”만 쓰므로, 체감상 생략이 많음. |
| **② 방향 필터 실패 시 스킵** | `findStreetViewInDirection`이 null(전방 ±90° 밖 pano만 있음)이면 **해당 샘플을 아예 추가하지 않음** → 구간 공백 발생. |
| **③ 온디맨드 트리거 늦음** | `currentIdx >= lastPano.pathIndex - 50` 일 때만 다음 구간 요청. 50 인덱스(경로 2m 밀도 기준 ≈100m) 전에 요청하므로, 고속 주행 시 캐시 끝에 도달한 뒤에도 다음 세그먼트가 도착하기 전에 “끝”을 보여 줄 수 있음. |
| **④ 세그먼트 크기 150m** | 한 번에 150m만 추가. 요청이 늦거나 네트워크가 느리면, 캐시가 비는 구간이 생김. |

---

## 3. 수정 방안 (연속 디스플레이 우선)

| 항목 | 변경 내용 | 목적 |
|------|-----------|------|
| **① 샘플 간격** | 15m → **10m** | 경로 상 파노라마 밀도 증가, 생략 감소. |
| **② 방향 필터 실패 시 폴백** | `findStreetViewInDirection`이 모든 radius에서 null이면 **`findStreetView(pathPoint, 30)`** 호출. 반환 pano가 있으면 **주행 방향 heading만 경로 기준으로 계산**해 PanoDataItem 추가. | 해당 구간에 “아무 pano도 없음”이 되지 않도록 함 (연속성 우선). |
| **③ 온디맨드 트리거** | `lastPano.pathIndex - 50` → **`lastPano.pathIndex - 150`** | 더 일찍 다음 구간 요청해, 캐시 소진 전에 세그먼트 도착하도록 함. |
| **④ 세그먼트 크기** | 150m → **200m** | 한 번에 더 많은 구간을 채워, 끊김 구간 감소. |
| **⑤ 초기 pre-fetch** | 첫 구간 150m·15m 유지 또는 **200m·10m** (20개 샘플) | 시작 직후에도 더 촘촘한 연속 디스플레이. |

---

## 4. 구현 요약

- **preFetchStreetViewData**:  
  - `intervalM` 기본값 15 → **10**.  
  - 방향 필터로 item을 얻지 못한 샘플에 대해 **findStreetView(pathPoint, 30)** 폴백 후, 성공 시 heading만 경로 기준으로 계산해 PanoDataItem push.
- **온디맨드**:  
  - 조건 `currentIdx >= lastPano.pathIndex - 50` → **`lastPano.pathIndex - 150`**.  
  - 세그먼트 `distAtLast + 150` → **`distAtLast + 200`** (한 번에 200m 구간 로드).
- **초기 pre-fetch**:  
  - `maxDistanceM: 150`, `intervalM: 15` → **`maxDistanceM: 200`, `intervalM: 10`** (선택).

이에 따라 **연속적인 거리뷰 디스플레이**를 우선하고, 생략을 줄이는 방향으로 코드 수정함.
