## 2. API 키 보안

### 2.1 Google Maps API 키 (GOOGLE_MAPS_API_KEY)

| 항목 | 현황 | 위험도 |
|------|------|--------|
| **저장 위치** | 환경 변수 (`process.env.GOOGLE_MAPS_API_KEY`) | ✅ 적절 |
| **클라이언트 노출** | Vite `define`으로 빌드 시 번들에 주입됨 (`vite.config.ts` 64행) | ⚠️ 불가피 |
| **실제 사용** | `App.tsx`에서 스크립트 URL에 포함: `maps.googleapis.com/maps/api/js?key=${apiKey}` | ⚠️ 브라우저에서 키 노출 |

**설명:**  
Google Maps JavaScript API는 클라이언트에서 키를 사용하는 구조이므로, **키가 브라우저에 노출되는 것은 구조적으로 피할 수 없음**. 따라서 노출 자체보다 **키 남용 방지 설정**이 중요함.

**권장 조치 (필수):**

1. **Google Cloud Console에서 API 키 제한**
   - **애플리케이션 제한:** "HTTP 리퍼러(웹사이트)" 선택 후, 허용 도메인만 등록  
     예: `https://your-app.vercel.app/*`, `http://localhost:*`
   - **API 제한:** "키 제한"에서 **Maps JavaScript API**, **Maps Street View API** 등 실제 사용하는 API만 선택
   - 이렇게 하면 타 도메인·타 앱에서 동일 키로 Maps 호출이 불가능해져, 유출 시 피해를 줄일 수 있음

2. **키 값 관리**
   - `.env`, `.env.local`에만 보관 (현재 `.gitignore`에 포함됨 ✅)
   - **`.env` 파일을 저장소에 커밋하지 않음** (현재 미커밋 ✅)
   - Vercel 등 배포 환경에서는 "Environment Variables"에만 등록하고, 빌드 로그·스크린샷에 키가 나오지 않도록 주의

3. **문서화**
   - `.env.example`에 `GOOGLE_MAPS_API_KEY=` (값 없이) 추가하고, README에 "Google Cloud Console에서 Maps JavaScript API·Street View API 활성화 후 키 발급 및 위 제한 설정" 안내 권장

## 3. 서버리스 API 보안 (Vercel `/api/*`)

### 3.1 API 키·비밀

- `api/nominatim-search.js`, `api/nominatim-reverse.js`, `api/osrm-route.js` 모두 **API 키를 사용하지 않음** ✅  
- Nominatim·OSRM은 공개 서비스이며, 프록시만 수행함.

### 3.2 CORS 설정

| 파일 | 설정 | 위험도 |
|------|------|--------|
| nominatim-search.js | `Access-Control-Allow-Origin: '*'` | ⚠️ 주의 |
| nominatim-reverse.js | `Access-Control-Allow-Origin: '*'` | ⚠️ 주의 |
| osrm-route.js | `Access-Control-Allow-Origin: '*'` | ⚠️ 주의 |

**설명:**  
`*`는 **어떤 출처에서든** 해당 API를 호출할 수 있게 한다.  
- **장점:** 별 도메인에서 SPA 배포 시 CORS 이슈 없음.  
- **단점:** 타 사이트가 사용자 브라우저를 통해 **당사 Vercel API를 프록시처럼 사용**할 수 있어, Nominatim 1 req/s 제한·OSRM 사용량이 타 사이트 요청까지 합산될 수 있음.

**권장 조치:**

- **옵션 A:** 배포 도메인이 고정된 경우, `Access-Control-Allow-Origin`을 해당 출처로 한정  
  예: `https://your-app.vercel.app`
- **옵션 B:** 계속 `*`를 쓸 경우, Vercel에서 **요청 빈도/할당량 모니터링** 후 필요 시 Rate Limit(예: Upstash 등) 도입 검토

### 3.3 입력 검증

| API | 입력 | 현재 처리 | 권장 |
|-----|------|-----------|------|
| nominatim-search | `q` | `encodeURIComponent(q)` | ✅ 적절. 과도한 길이 제한(예: 500자) 권장 |
| nominatim-reverse | `lat`, `lon` | 쿼리로 전달 | 숫자·범위 검증 권장 (위도 -90~90, 경도 -180~180) |
| osrm-route | `profile`, `coords` | 쿼리로 전달 | `profile`은 `cycling`/`foot` 화이트리스트; `coords`는 형식 검증(숫자, 구분자, 길이) 권장 |

- **coords**가 URL 경로에 그대로 들어가므로 (`/route/v1/${profile}/${coords}`), 슬래시·인코딩 등으로 경로 조작이 되지 않도록 **형식 검증(정규식 등)**을 두는 것이 안전함.

## 4. 기타 보안 사항

### 4.1 환경 설정·비밀 관리

| 항목 | 현황 |
|------|------|
| `.env` / `.env.local` | `.gitignore`에 포함됨 ✅ |
| `.env.example` | 없음 → **추가 권장** (키 이름만 기재, 값 비공개) |
| 저장소에 하드코딩된 키 | 없음 ✅ |

### 4.2 Dropbox 플레이리스트 URL (배경 음악)

- **위치:** `App.tsx` 내 `PLAYLIST` 배열에 Dropbox 공유 링크(rlkey, st 등 쿼리 포함)가 **하드코딩**되어 있음.
- **위험:**  
  - 저장소가 공개일 경우, 해당 URL이 그대로 노출됨.  
  - 링크를 알면 누구나 스트리밍 가능 → 대역폭·용량 소진, 링크 비활성화 등으로 이어질 수 있음.
- **권장:**  
  - **옵션 A:** 재생 목록 URL을 환경 변수(예: `MUSIC_PLAYLIST_JSON`)나 설정 파일로 분리하고, 해당 파일은 `.gitignore` 처리.  
  - **옵션 B:** 백엔드(또는 Vercel 함수)에서 음원 URL을 반환하고, 클라이언트는 “플레이리스트 ID”만 전달하도록 변경해 URL 자체를 저장소·클라이언트에 두지 않기.

### 4.3 localStorage

- **저장 항목:** `favorite_routes`, `recent_places` (경로 정보·검색어 등).
- **평가:**  
  - 민감한 개인정보(비밀번호, 결제 정보 등)는 저장하지 않음 ✅  
  - `JSON.parse(localStorage.getItem(...))` 결과를 React 텍스트로만 렌더링하면 기본 이스케이프로 XSS 위험은 낮음.  
  - 다만 **조작된 데이터**가 들어와도 앱이 깨지지 않도록, 파싱 실패 시 기본값 반환 등 **방어 코드**가 있으면 좋음.

### 4.4 XSS·인젝션

- **검색 결과:** `dangerouslySetInnerHTML` / `eval` / `document.write` 미사용 ✅  
- **SVG 아이콘:** `App.tsx`에서 마커 아이콘용 SVG를 문자열로 조합한 뒤 `encodeURIComponent(svg)`로 data URL 생성. `dataUrl`은 앱이 로드한 이미지 데이터로 채워지므로, 사용자 입력이 직접 들어가는 구조는 아님.  
- **API 응답:** Nominatim·OSRM 응답을 그대로 HTML에 넣는 부분이 없고, 주로 좌표·주소 문자열로 사용됨 → 일반적인 사용 범위에서는 XSS 위험 낮음.

### 4.5 헤더·CSP

- **Content-Security-Policy, X-Frame-Options, X-Content-Type-Options** 등 보안 헤더는 **코드/설정에서 미설정**으로 확인됨.
- **권장:**  
  - Vercel에서 **Headers** 설정으로 다음 추가 검토:  
    - `X-Content-Type-Options: nosniff`  
    - `X-Frame-Options: DENY` (또는 SAMEORIGIN, 필요에 따라)  
    - CSP는 지도·Street View·esm.sh 등 외부 스크립트/이미지 도메인을 허용해야 하므로, 단계적으로 도입 후 테스트 권장.

### 4.6 의존성

- **npm audit:** 정기 실행 권장 (`npm audit`, 필요 시 `npm audit fix`).  
- 보고서 작성 시점에는 별도 취약점 스캔을 수행하지 않았으므로, **배포 전 또는 정기 점검 시** `npm audit` 실행을 권장함.

### 4.7 PWA·Service Worker

- `index.html`에서 매 로드 시 Service Worker 등록 해제·캐시 삭제를 수행하는 스크립트가 있음.  
- 보안 관점: SW로 인한 오래된 스크립트 캐시 제거로, **캐시된 취약 버전 노출 기간**을 줄이는 효과는 있음.  
- `manifest.json`에는 민감 정보 없음 ✅
