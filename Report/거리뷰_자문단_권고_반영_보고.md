## 1. 반영한 항목 (우선순위 순)

### 1순위: Fallback 무한 반복 차단 ✅

- **getPanoramaWithFallback**
  - `ZERO_RESULTS`, `OVER_QUERY_LIMIT` 수신 시 **DEFAULT 재시도 없이** 즉시 `null` 반환.
  - 불필요한 2차 호출 및 “실패 → 재시도 → 재시도” 연쇄 차단.
- **preFetchStreetViewData**
  - 샘플당 시도 횟수 **상한 2회** (`MAX_FALLBACK_PER_SAMPLE = 2`):  
    (1) 방향 필터 반경 1회, (2) 방향 무시 폴백 1회 후 **중단**.
- **실시간 검색** (캐시 없을 때)
  - 전체 시도 **상한 3회** (`MAX_REALTIME_SV_ATTEMPTS = 3`):  
    현재 위치 1회 → 방향 무시 폴백 1회 → 전방 한 지점 1회.  
  - 초과 시 “거리뷰 없음” 표시 후 검색 중단.
  - 경고 노출 조건: 연속 실패 3회 이상 시 (`svErrorCount > 2`).

### 4순위: 반경 확대 + 1회 제한 ✅

- **탐색 반경**
  - 기존 30/20/15/50m 다단계 제거 → **200m 단일 반경** 사용 (`STREETVIEW_SEARCH_RADIUS_M = 200`).
  - “실제 pano는 80m, 120m 떨어져 있음” 같은 경우에도 탐색 가능하도록 조정.
- **preFetchStreetViewData**
  - 샘플당 **200m로 1회** 방향 필터 검색, 실패 시 **200m로 1회** 방향 무시 검색 후 종료 (위 1순위와 동일, 2회 상한).
- **실시간 검색**
  - 동일하게 **200m** 반경 사용, 시도 횟수는 위와 같이 3회로 제한.

## 2. Status 처리 (자문단 4단계 반영)

| Status            | 처리 |
|-------------------|------|
| OK                | 정상 반환 |
| ZERO_RESULTS      | **즉시 중단**, DEFAULT 호출 안 함 |
| OVER_QUERY_LIMIT  | **즉시 중단**, DEFAULT 호출 안 함 |
| 기타              | DEFAULT 1회만 시도 후 결과 반환 |

---

## 3. 상수 정리 (App.tsx)

| 상수 | 값 | 용도 |
|------|-----|------|
| `UNRECOVERABLE_STATUS` | `['ZERO_RESULTS','OVER_QUERY_LIMIT']` | 재시도/폴백 금지할 status |
| `STREETVIEW_SEARCH_RADIUS_M` | 200 | 거리뷰 탐색 반경(m) |
| `MAX_FALLBACK_PER_SAMPLE` | 2 | 샘플당 최대 시도 횟수 (프리페치) |
| `MAX_REALTIME_SV_ATTEMPTS` | 3 | 실시간 검색 최대 시도 횟수 |

## 4. 2·3순위 (panoId 기반·캐싱)에 대해

- **panoId 기반 구조**(연결 이동):  
  현재는 경로 샘플별로 1~2회만 호출하도록 제한해 두었고,  
  이후 단계에서 `panorama.getLinks()` 기반 “한 번 찾고 연결로 이동” 구조 도입을 검토할 수 있음.
- **캐싱**:  
  동일 경로/세그먼트 재주행 시 `route.panoData` 재사용은 이미 이루어지며,  
  `Map<lat_lng, panoId>` 등 세그먼트 단위 캐시 확장은 추후 개선 과제로 둠.

---

## 5. 기대 효과

- **있는데도 안 보이는 문제**: 200m 반경으로 탐색해, 도로와 촬영 위치가 수십 m 어긋나도 발견 가능성 증가.
- **비용 폭증 위험**:  
  - 샘플당 최대 2회(프리페치), 실시간 최대 3회 시도.  
  - `ZERO_RESULTS`/`OVER_QUERY_LIMIT` 시 추가 DEFAULT 호출 제거로 불필요한 호출 감소.

이상으로 자문단 권고 1순위·4순위를 반영하였고, 2·3순위는 추후 단계에서 적용할 수 있도록 정리하였습니다.
