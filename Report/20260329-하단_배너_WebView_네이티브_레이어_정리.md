# 하단 배너 · WebView · 네이티브 레이어 정리 (PM 계획 승인본)

## 1. Chrome DevTools(Inspect) 한계

- **AdMob 배너·전면 광고**는 **Android/iOS 네이티브 뷰**로 그려지며 **WebView DOM 트리에 포함되지 않음**.
- 원격 디버깅 Elements 패널에는 **웹 레이어만** 표시되므로, 광고 노드가 **없는 것이 정상**이다.
- “광고가 안 보이고 반투명 바도 안 보인다” → **둘이 같은 DOM 요소**라는 의미가 **아님**. (조건·환경 차이로 동시에 관찰되지 않을 수 있음.)

## 2. 앱 구조 요약

```
[ 네이티브 ] AdMob BannerAdView (형제: WebView)
[ WebView ]
  └ #root
       └ 맵 div (z-10 등) — Google Maps 내부 .gm-style (로고·저작권·스케일 등)
       └ OSM 저작권 링크 (앱이 추가하는 <a>)
       └ 패널·모달 (z-45 ~ z-1100)
```

- 과거 **`z-[5] bg-white` 전폭 띠**: `rootBottomBannerPadPx===0 && stackBannerPadPx>0` 일 때만 (가로·네이티브 등). **불투명** (`bg-white`). 반투명 현상의 유일 원인은 아님.
- **`stackBannerPadPx` / `rootBottomBannerPadPx`**: 배너 높이 예약과 루트 `bottom` 조정. 광고 `isAdLoaded`와 **직접 바인딩된 prop은 아님** (이벤트로 `bannerReservedPx` 갱신).

## 3. 반투명 띠 후보 (검증 매트릭스)

| 후보 | Inspect에서 식별 | 비고 |
|------|------------------|------|
| OSM 링크 `bg-white/55` | 가능 (`<a>`) | **불투명으로 교체** 권장 |
| Google Maps **scaleControl** (BOTTOM_CENTER) | 맵 컨테이너 **내부** | 네이티브에서 **끄기** 실험 (거리는 경로/저장 데이터로 확인 가능) |
| Google 저작권/로고 줄 | 맵 **내부** | 정책·스타일 제약, 전역 CSS는 취약 |
| **거리뷰 `.gm-iv-address` 등** | 맵/SV **내부** | 하단 밝은 주소·정보 패널 — 배너 위 반투명 띠로 착시 가능 |
| 고도 패널 `bg-white/95` + blur | 가능 | 우하단, 펼침 시 넓게 덮음 |
| 루트 `bg-slate-900` | 루트 div | 흰 띠 제거 시 **검은 빈틈** 노출 가능 |

## 4. 본 브랜치에서 적용한 조치 (요약)

1. OSM: **반투명 배경 제거** → 불투명 칩(`bg-white` + 둥근 모서리), **z-index를 맵보다 위·고정 패널보다 낮게** 조정해 맵 위 가독성 유지.
2. **Capacitor 네이티브**에서만 **`scaleControl: false`** → 하단 중앙 Google 스케일 UI 제거(반투명 밴드 의심 구간 축소).
3. `MainActivity`: `bringChildToFront` 지연 실행 콜백 **`onDestroy`에서 제거** (누수·백그라운드 동작 방지).
4. **추가 (반투명 잔존 시)**: `StreetViewPanorama`에 **address/imageDate 등 컨트롤 명시 false** + `main.css`에서 **`.gm-iv-address` 등 거리뷰 하단 밝은 패널 숨김** (Google DOM 변경 시 무효 가능).
