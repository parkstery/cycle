# 260430-주행 마커 이미지 변경 보고서

## 목적

- 시뮬레이션 주행 시 지도에 표시되는 **주행 위치 마커**를 정적 이미지 한 장만 이동시키는 방식에서 벗어나, **미세한 움직임(흔들림)** 으로 주행감을 살린다.
- 옆모습 실루엣만으로는 좌우 흔들림이 시각적으로 약하므로 **후면(뒤에서 본) 실루엣** 에셋을 도입해 효과를 검증한다.
- 스마트폰(WebView/Capacitor) 환경에서 **동일 파일명 PNG가 갱신되지 않는 현상**을 줄이기 위해 **캐시 무효화 전략**을 적용한다.
- 후면 마커 PNG의 **불투명 검정 배경**이 지도 위에 사각형으로 보이는 문제를 제거하기 위해 **알파(투명) 배경**으로 재처리한다.

## 적용 범위

| 구분 | 경로·파일 |
|------|-----------|
| 마커 URL·프리로드·아이콘 조합 | `App.tsx` |
| 마커 래스터 에셋 | `public/cycling_position_marker.png` (옆모습, 기존), `public/cycling_position_marker_rear.png` (후면) |
| 배경 투명 처리 스크립트 | `scripts/make-marker-transparent.mjs` |
| PNG 처리용 도구 | `package.json` — `sharp` (devDependency) |

## 구현 요약

### 1) SMIL 기반 흔들림(회전)

- Google Maps `Marker` 아이콘으로 **data URL SVG**를 사용하는 기존 패턴을 유지한다.
- PNG는 `fetch` → `FileReader`로 **base64 data URL**에 넣은 뒤, SVG `<image href="...">`로 참조한다. (data URI SVG에서 외부 `http(s)` 이미지 참조가 막히는 제약을 피하기 위함.)
- SVG 내부에 `<animateTransform type="rotate" ...>` 를 두어 **약 ±3°**, 축 `(20, 22)` 부근, **1.2초 주기**로 부드럽게 좌우로 흔들리게 한다.
- 진행 방향에 따라 `scale(-1,1)` 로 **좌우 반전**하는 기존 로직은 그대로 둔다.

### 2) 에셋 전환: 옆모습 → 후면

- 후면 실루엣 파일: `public/cycling_position_marker_rear.png`
- 코드 상수 `CYCLING_POSITION_MARKER_URL`로 **한 곳에서** 로드 경로를 관리한다.
- 옆모습으로 되돌릴 때는 동일 상수에서 파일명만 `cycling_position_marker.png`로 바꾸고, 필요 시 **에셋 revision**을 함께 올린다.

### 3) 캐시 무효화 (`?v=` + revision)

- 상수 `CYCLING_MARKER_ASSET_REVISION`을 두고, 마커 요청 URL을  
  `'/cycling_position_marker_rear.png?v=' + CYCLING_MARKER_ASSET_REVISION` 형태로 만든다.
- **PNG 내용을 바꿀 때마다** revision 숫자만 올리면, 네이티브 WebView가 동일 경로를 붙잡는 경우에도 새 요청으로 받기 쉽다.
- 언인스톨 후에도 예전 그림만 보인다면, 대개 **패키지에 포함된 웹 자산이 예전 빌드**이거나, **스토어에 올린 바이너리가 최신 `build`/`cap sync` 결과가 아님**인 경우가 많다. revision은 그중 **클라이언트 캐시 키 분리**를 돕는다.

### 4) 검정 배경 제거(투명 PNG)

- `sharp`로 픽셀을 읽어, **어두운 배경·저채도 회색(안티앨리어싱 테두리)** 을 알파 0으로 만든다.
- 재실행:  
  `node scripts/make-marker-transparent.mjs public/cycling_position_marker_rear.png`  
  (다른 PNG에도 동일 인자 패턴으로 적용 가능)
- 임계값은 `scripts/make-marker-transparent.mjs` 의 `shouldBeTransparent` 에 정의되어 있다. 테두리 잔상이 남거나 실루엣이 잘리면 이 함수의 **밝기·채도 조건**을 조정한다.

## 최종 동작 사양 (현재 기준)

- **표시 에셋:** `public/cycling_position_marker_rear.png` (투명 배경 처리 후)
- **로드 URL:** `/cycling_position_marker_rear.png?v=<CYCLING_MARKER_ASSET_REVISION>` (현재 revision **4**)
- **프리로드:** 앱 로드 시 한 번 `fetch` 후 `cyclingMarkerDataUrlRef`에 data URL 저장
- **아이콘:** data URL이 준비되면 SVG+SMIL+`<image>` 조합의 data URL을 `Marker`에 설정; 미준비 시 폴백으로 동일 `CYCLING_POSITION_MARKER_URL` 직접 사용

## UX·품질 효과

- 작은 지도 아이콘에서도 **미세한 롤링**이 보여 주행 중 “살아 있는” 마커로 인지하기 쉽다.
- 후면 실루엣은 좌우 대칭에 가까워 **흔들림과 방향 반전**이 함께 읽히기 좋다.
- 투명 배경으로 **지도 타일 위 검은 사각형** 노출이 사라진다.
- revision·재빌드 절차로 **모바일에서 옛 이미지가 남는 현상**을 완화한다.

## 비고

- Service Worker는 `public/sw.js` 및 `index.html` 스크립트에서 **unregister·캐시 삭제** 위주로 동작하므로, 본 이슈의 주된 원인은 SW보다 **번들 내 정적 파일 버전·캐시 키** 쪽에 두는 것이 타당하다.
- 옆모습으로 다시 기본 전환할 경우: `CYCLING_POSITION_MARKER_URL`의 파일명 변경 + **revision 증가** + 필요 시 `make-marker-transparent.mjs` 로 동일 배경 처리 권장.
