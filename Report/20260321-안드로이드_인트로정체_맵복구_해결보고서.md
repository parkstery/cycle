| 구분 | 내용 |
|------|------|
| **초기 현상** | 인트로(스플래시) 이미지는 보이나, 이후 **지도와 UI 버튼이 나타나지 않고 멈춘 것처럼** 보임 |

## 2. 원인 분석 (다단계)

문제는 **단일 원인**이 아니라, **① 빌드 시 API 키 미주입 → ② Vite 설정 충돌 → ③ 로컬 환경 변수 미설정 → ④ Google Cloud 키 제한(리퍼러)** 순으로 겹쳐 발생했습니다.

### 2.1 1차 원인: `GOOGLE_MAPS_API_KEY` 빌드 미주입

- 앱은 `App.tsx`에서 **Google Maps JavaScript API**를 동적 스크립트로 로드합니다.
- Vite는 `vite.config.ts`의 `define`으로 `process.env.GOOGLE_MAPS_API_KEY`를 클라이언트 번들에 넣습니다.
- **Android/로컬 빌드** 시점에 환경 변수가 없으면 키가 비어 있고, 그 결과:
  - `maps.googleapis.com` 요청이 발생하지 않거나,
  - 맵 초기화·화면 전이 게이트가 열리지 않아 **맵·버튼이 보이지 않는 상태**로 남을 수 있음.
- 웹(Vercel) 배포와 달리, **로컬·Android Studio 빌드에는 Vercel의 Environment Variables가 자동 적용되지 않음.**

### 2.2 2차 원인: `vite.config.ts`의 `process.env` 정의 충돌

- 기존 설정에서 `'process.env': {}`처럼 **`process.env` 전체를 빈 객체로 치환**하는 패턴이 있으면,  
  `process.env.GOOGLE_MAPS_API_KEY` 접근이 **실제 키 값과 무관하게 무효화**될 수 있습니다.
- 즉 `.env.local` 등에 키를 넣어도 **번들에 반영되지 않는** 현상이 발생할 수 있습니다.

### 2.3 3차 원인: 로컬에 키 입력 위치 부재·미저장

- 키는 **프로젝트 루트의 `.env.local`**(또는 동등한 방식)에 두고, **`npm run build` → `npx cap sync android`** 로 다시 반영해야 합니다.
- 파일 미저장·빌드 미실행 시 `dist` 번들에는 여전히 빈 키가 남습니다.

### 2.4 4차 원인: Google Cloud API 키의 HTTP 리퍼러 제한

- 키가 번들에 들어간 뒤에도, Capacitor WebView의 페이지 출처는 **`https://localhost`** 에 가깝습니다.
- API 키가 **Vercel 도메인 등 웹 URL만** HTTP 리퍼러로 허용되어 있으면, 앱에서는 Google이 요청을 거부하고 **“Maps를 올바르게 로드하지 못했다”** 류의 오류 UI가 표시됩니다.

### 2.5 부수 이슈 (증상 완화와 무관·참고)

- `public/icon-512.png` 등 자산이 없으면 **에셋 404 로그**가 남을 수 있으나, 본 이슈의 핵심은 **Maps API 키 주입·제한**입니다.
- Logcat의 `Choreographer: Skipped N frames` 등은 에뮬레이터/초기 로딩 부하에 흔히 나타나는 메시지로, 이번 “맵 미표시”의 직접 원인으로 보기 어렵습니다.

## 3. 해결 과정 (시간 순)

### 3.1 코드·빌드 설정 보강

1. **`vite.config.ts`**
   - `loadEnv` 결과에 더해 `process.env` 및 대체 이름(`VITE_GOOGLE_MAPS_API_KEY`, 오타 대비 변수 등)에서 키를 읽도록 보강.
   - **`define`에서 `process.env`를 `{ GOOGLE_MAPS_API_KEY }` 형태로 일관되게 치환**하여, 빈 `process.env`로 키가 지워지지 않도록 수정.

2. **`App.tsx`**
   - 빌드 주입 실패 시를 대비해 `window.__GOOGLE_MAPS_API_KEY__`, `meta[name="GOOGLE_MAPS_API_KEY"]` 등 **런타임 보조 경로** 유지.
   - 스크립트 URL에 `encodeURIComponent(apiKey)` 적용.
   - 인증 실패 시 디버깅을 위해 **`gm_authFailure`** 에서 Logcat용 메시지 출력.

3. **`.env.local` 템플릿**
   - 로컬/Android 빌드용으로 `GOOGLE_MAPS_API_KEY=` 항목을 두고, 실제 키는 로컬에서만 채우도록 안내.

### 3.2 운영 절차 (반드시 재빌드·동기화)

1. `.env.local`에 `GOOGLE_MAPS_API_KEY` 설정 후 **저장**.
2. `npm run build`
3. `npx cap sync android`
4. Android Studio에서 앱 **재설치 후 실행**

### 3.3 Google Cloud Console 설정

1. 해당 API 키의 **HTTP 리퍼러**에 **`https://localhost/*`** (필요 시 `http://localhost/*`) 추가.
2. **Maps JavaScript API** 등 필요 API가 키의 API 제한 목록에 포함되어 있는지 확인.
3. 프로젝트 **결제 계정** 연결 확인.

### 3.4 문서화

- Capacitor Android 전용 키·리퍼러 이슈를 정리한 가이드:  
  `Report/20260321-GOOGLE_MAPS_CAPACITOR_ANDROID_키설정.md`

## 5. 결론

- **인트로 이후 맵·버튼이 보이지 않던 현상**의 핵심은 **Android/로컬 빌드에서 `GOOGLE_MAPS_API_KEY`가 번들에 들어가지 않았던 것**과, 이를 가린 **`vite.config.ts`의 `process.env` 정의 방식**이었습니다.
- 키가 들어간 뒤에는 **Capacitor 출처(`https://localhost`)에 맞는 Google Cloud 키 제한**이 없어 **Maps 로드 거부 UI**가 나타났고, **리퍼러 허용 목록 보완**으로 해결되었습니다.
- **Gradle만의 문제는 아니었으며**, **웹 자산 빌드(Vite) + 환경 변수 + `cap sync` + Cloud Console 키 정책**이 함께 맞아야 동일 증상이 재발하지 않습니다.

---

## 6. 재발 방지 권장

1. CI/Android 릴리스 파이프라인에 **`GOOGLE_MAPS_API_KEY`(또는 동등 변수)** 를 필수로 두고, 누락 시 빌드 실패 또는 명시적 경고.
2. `.env.example`에 “로컬·Android 빌드 시 필수” 주석 유지.
3. 웹 전용 키와 앱(WebView)용 키를 **분리**하거나, 한 키 사용 시 **Vercel 도메인 + `https://localhost/*`** 를 동시에 허용.
