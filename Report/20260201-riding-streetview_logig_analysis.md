## Riding 시뮬레이션 및 거리뷰 디스플레이 로직 분석 보고서

본 보고서는 현재 애플리케이션에 구현된 사이클링 시뮬레이션 엔진과 스트리트뷰 동기화 및 렌더링 최적화(이중 버퍼링) 로직에 대한 상세 분석 내용입니다.
1. 시뮬레이션 코어 엔진 (Simulation Engine)
주행 시뮬레이션은 경로 데이터를 기반으로 사용자의 위치를 실시간으로 업데이트하며 속도에 맞춰 마커와 시점을 이동시킵니다.
A. 경로 데이터 전처리 (Densification)
보간법(Interpolation) 적용: Google Maps 또는 OSRM API로부터 받은 경로 데이터(Waypoints)는 점과 점 사이의 거리가 먼 경우가 많습니다. 부드러운 이동을 위해 경로를 약 2미터 단위로 촘촘하게 나누는 'Densification' 과정을 거쳐 시뮬레이션용 경로 배열(densifiedPath)을 생성합니다.
정밀 좌표 우선: 주소 검색 시 반환된 텍스트 주소보다, 클릭 지점의 정확한 위도/경도 객체(LatLng)를 우선 사용하여 도로 스내핑(Road Snapping) 오차를 줄입니다.
B. 타임 루프 및 속도 제어
가변 프레임 레이트: 고정된 setInterval 대신 setTimeout을 사용하여 재귀적으로 호출됩니다. 다음 이동 지점까지의 거리와 현재 설정된 속도(km/h)를 계산하여, 다음 프레임 호출까지의 지연 시간(Delay)을 동적으로 결정합니다.
마커 동기화: 매 프레임마다 지도상의 마커 위치를 업데이트하고, 현재 위치와 다음 위치 사이의 각도(Heading)를 계산하여 마커와 스트리트뷰의 시선 방향을 회전시킵니다.
2. 스트리트뷰 동기화 및 검색 전략 (Synchronization & Search Strategies)
시뮬레이션 좌표와 실제 구글 스트리트뷰 파노라마 데이터(Pano ID)를 매칭하기 위해 다층적인 검색 및 복구 전략을 사용합니다.
A. 세마포어(Semaphore) 제어
중복 요청 방지: 스트리트뷰 API 요청이 비동기로 처리되는 동안 중복 실행을 막기 위해 isSvSearching 플래그(세마포어)를 사용합니다. 이전 검색이 완료되지 않았다면 새로운 검색을 스킵하여 성능 저하를 방지합니다.
검색 임계값(Threshold): 현재 보고 있는 파노라마 위치와 시뮬레이션 위치의 거리가 15미터 이상 벌어졌을 때만 새로운 파노라마를 검색합니다. 이는 불필요한 API 호출을 줄이고 화면 떨림을 방지합니다.
B. 3단계 검색 및 복구 알고리즘 (Search & Recovery)
데이터가 없는 구간(터널, 산길 등)이나 데이터 불일치를 해결하기 위해 다음 3단계 전략을 순차적으로 실행합니다.
전략 1 (Standard): 현재 좌표 반경 50m 내에서 가장 가까운 파노라마를 검색합니다.
전략 2 (Look-ahead): 전략 1 실패 시, 진행 방향으로 1~5단계 앞선 미래 좌표들에서 파노라마를 검색합니다. 데이터가 유실된 구간을 자동으로 건너뛰어(Skip) 시뮬레이션이 멈추지 않게 합니다.
전략 3 (Fallback): 위 전략 모두 실패 시, 현재 위치 반경을 100m로 넓혀 광범위하게 재검색합니다.
3. 디스플레이 최적화: 하이브리드 이중 버퍼링 (Hybrid Double Buffering)
검은 화면(로딩 화면) 노출을 방지하고 부드러운 전환을 위해 **'네이티브 연결'**과 '이중 버퍼링 교체' 방식을 상황에 따라 선택적으로 적용합니다.
A. 구조 (Architecture)
듀얼 뷰어(Dual Viewers): 화면에 panorama1, panorama2라는 두 개의 스트리트뷰 인스턴스를 겹쳐서 생성해 둡니다.
Z-Index 제어: visiblePanoIdx 상태를 통해 현재 활성화된 뷰어의 우선순위(Z-Index)를 조절하여 사용자에게 보여줄 화면을 결정합니다.
B. 전환 로직 (Transition Logic)
새로운 파노라마 ID가 발견되었을 때, 다음 두 가지 경우 중 하나로 분기합니다.
Case 1: 연속된 경로 (Smooth Glide)
조건: 현재 파노라마의 연결 고리(Links) 데이터에 새로운 파노라마 ID가 존재할 경우.
동작: 뷰어를 교체하지 않고 현재 활성화된 뷰어에서 setPano를 실행합니다.
효과: 구글 맵 API가 기본 제공하는 '공간 이동 애니메이션(Motion Blur)' 효과가 적용되어 물 흐르듯 자연스럽게 이동합니다.
Case 2: 비연속 구간/점프 (Teleport via Swap)
조건: 연결 고리가 끊겨 있거나 거리가 멀어 점프해야 하는 경우.
동작:
사용자 눈에 보이지 않는 **백그라운드 뷰어(Hidden Viewer)**에 먼저 새로운 이미지를 로딩합니다.
로딩 완료 신호(links_changed 이벤트)를 감지하거나 타임아웃(0.5초)을 기다립니다.
준비가 완료되면 즉시 Z-Index를 변경하여 백그라운드 뷰어를 최상단으로 올립니다(Swap).
효과: 이미지가 로딩되는 동안의 검은 화면(Black Screen)이 사용자에게 노출되지 않고, 즉시 완성된 화면으로 전환됩니다.
4. AI 코칭 및 부가 기능 연동
실시간 경사도 분석: 경로상의 고도 데이터를 분석하여 현재 경사도(Slope)를 계산합니다.
AI 코치: 일정 주기마다 Gemini API를 호출하여 경사도, 속도, 이전 저항값을 기반으로 "저항 3으로 변경하세요", "업힐이니 일어서세요" 등의 구체적인 코칭 메시지를 생성하고 음성(TTS)으로 출력합니다.
상태 동기화: 시뮬레이션이 일시 정지되거나 종료될 때, 오디오 및 스트리트뷰 상태를 즉시 정리하여 리소스 누수를 방지합니다.
