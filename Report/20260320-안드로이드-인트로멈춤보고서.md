# 안드로이드 전환 “검은 화면/맵·버튼 미노출” 문제 원인 분석 보고서

## **안드로이드 전환 “검은 화면/맵·버튼 미노출” 문제 원인 분석 보고서**

### **1) 현상 요약**

- 안드로이드 앱 실행 시 인트로(이미지)는 보이지만 이후 화면에서 **맵과 버튼 콘트롤이 전혀 표시되지 않음(멈춘 상태)**

### **2) 관측된 로그 기반 사실**

1. Capacitor/WebView 초기화 및 정적 리소스 로딩은 정상 범주
    - `Capacitor: Loading app at https://localhost`
    - `assets/index-*.js`, `index-*.css`, 이미지(`cycle-road.png`, `bike_conti-128.png` 등) 요청/로딩이 확인됨
    - `App started` / `App resumed` 흐름도 존재
2. 그런데 “맵 API 관련 이벤트” 및 “스크립트 로딩 흔적”이 로그 필터에서 확인되지 않음
    - `maps.googleapis.com`, `__cycleSvApiReady` 관련 문구가 **findstr 필터 결과에 잡히지 않음**
    - `Capacitor/Console`, `GlobalError`, `TypeError` 등 치명 JS 예외 키워드도 동일 구간에서 **미노출**
3. 브라우저/렌더링 측 메트릭은 이상 신호 존재
    - `Invalid first_paint (unset)`이 반복적으로 관측됨
    - 이는 “초기 화면 페인팅이 정상 완료되지 않음”을 시사(단, “React 마운트 100% 실패”까지는 단정 불가)

### **3) 핵심 원인(우선순위 1): 빌드 시 `GOOGLE_MAPS_API_KEY` 미주입 → Maps JS 로더 코드가 사실상 동작하지 않음**

이번 케이스는 **API key 자체 문제 가능성**이 매우 높습니다. 이유는 단순히 “runtime에서 에러가 없다”가 아니라, **빌드 산출물(dist 번들)에서 Maps 로딩 코드 흔적이 확인되지 않기 때문**입니다.

- dist 번들(JS) 내부에서 다음 문자열이 검색되지 않음:
    - `maps.googleapis.com`
    - `__cycleSvApiReady`
    - `GOOGLE_MAPS_API_KEY`
- 프로젝트 구조상 Google Maps JS는 `App.tsx`에서 동적 스크립트를 주입하고, 그 주입은 `process.env.GOOGLE_MAPS_API_KEY` 존재 여부에 의존합니다.
- Vite는 `vite.config.ts`에서 `process.env.GOOGLE_MAPS_API_KEY`를 `define`으로 주입하는데, 이 값이 빌드 시점에 **undefined/공백**이면
    - `if (!apiKey) return;` 조건이 “빌드 단계에서 사실상 고정”되어,
    - 그 결과 Maps JS 스크립트 주입부가 번들에서 제거되거나(트리쉐이킹/상수폴딩),
    - 런타임에서도 `maps.googleapis.com` 요청이 일어나지 않는 상태가 됩니다.
- 이런 상태에서는 맵 초기화가 진행되지 않으며, 앱은 “인트로 이후 상태 전이(맵/버튼 노출 게이트)”를 열지 못해 **결과적으로 맵/버튼이 모두 안 보이는 화면**으로 남을 수 있습니다.

### **4) 보조/참고 요인**

1. `Capacitor: Unable to read file at path public/plugins`
    - 치명 크래시의 1차 원인이라기보다는 “플러그인 정적 파일/경로가 기대와 다름” 신호입니다.
    - 다만 이후 권한/플러그인 처리 흐름에 간접 영향을 줄 수 있으므로 “동시에 정리해야 할 리스크”로 남깁니다.
2. Geolocation 권한 프롬프트 관련 로그(`onGeolocationPermissionsShowPrompt`, “plugin to handle permission requestCode” 미탐)
    - `App paused/resumed`가 얽히는 타이밍 이슈가 있을 수 있어, 2순위 리스크입니다.
    - 다만 이번 케이스의 “Maps 이벤트 흔적 미노출” 증거가 더 강해 우선순위를 낮춥니다.

### **5) 결론(원인 1개로 좁히면)**

- **가장 유력한 단일 원인:** Android 빌드(또는 해당 환경)에서 `GOOGLE_MAPS_API_KEY`가 주입되지 않아, Google Maps JS 로딩/콜백이 아예 발생하지 않는 상태
- 그 결과: 맵 초기화/표시 게이트가 열리지 않아 **맵/버튼이 전부 미노출**되는 현상으로 연결

## **6) 권장 해결책(코드 작성 없이 실행 중심)**

1. 빌드가 수행되는 환경에서 `GOOGLE_MAPS_API_KEY`가 실제로 존재하는지부터 검증
    - 로컬 빌드라면: 빌드 전에 `.env.local` 또는 환경변수로 `GOOGLE_MAPS_API_KEY` 설정
    - CI/배포라면: Vercel/GitHub Actions/빌드 서버 Environment Variables에 설정
2. “키가 들어갔는지”를 검증하는 방법(런타임 대신 빌드 산출물 확인)
    - `dist/assets/index-*.js`에서 `maps.googleapis.com` 문자열이 존재하는지 확인
    - 존재하지 않으면 “API key/주입 로직 자체가 번들에서 제거된 것”이므로 키 주입부터 수정
3. 런타임에서 최종 확인
    - `maps.googleapis.com` 요청 및 `__cycleSvApiReady` 콜백 로그가 관측되는지 확인

---

## **7) 향후 유지관리 권장(재발 방지)**

- `GOOGLE_MAPS_API_KEY`를 “필수 빌드 조건”으로 취급해, 빌드/배포 파이프라인에서 누락 시 즉시 실패 또는 경고하도록 운영 규칙을 추가
- `.env.example`/문서에 “Android 빌드용 GOOGLE_MAPS_API_KEY 필수”를 명확히 표기
- `public/plugins` 경고는 별도 이슈로 태깅해, 플러그인 경로/자산 포함 정책을 정리
