# 안드로이드 상단 버튼 무반응 원인 및 해결 보고서

## 1) 이슈 개요

- 대상 앱: Indoor cycling 앱 (Capacitor + React + Google Maps/Street View)
- 발생 환경: Android Studio 가상폰(WebView)
- 증상:
  - `App Info` 버튼은 동작
  - `Search Places`, `Change Map Style`, `Show Street View Coverage` 버튼은 무반응
  - 웹 브라우저/브라우저 디바이스 모드에서는 정상 동작

---

## 2) 주요 관찰 로그

### A. 클릭 히트 테스트 결과

- `[HIT] ... svg null auto`
- `[HIT] ... IMG null auto`

해석:
- 상단 버튼 터치 시 버튼 본체가 아니라 내부 아이콘(`svg`, `img`) 또는 주변 레이어가 우선 히트되는 상황이 확인됨
- Android WebView에서 터치→클릭 승격이 불안정하거나, 상단 레이어 충돌 가능성이 높음

### B. 전역 예외 로그

- `Uncaught TypeError: Cannot read properties of undefined (reading 'cancel')`
- 스택상 `window.speechSynthesis.cancel()` 경로에서 반복 발생

해석:
- WebView 음성 API 환경 차이로 전역 예외가 발생
- 이 예외는 UI 이벤트 흐름을 악화시킬 수 있으나, 버튼 무반응의 직접 원인과는 분리해서 처리 필요

---

## 3) 원인 분석 (최종)

본 이슈는 **복합 원인**으로 판단됨.

1. **직접 원인(버튼 무반응): 상단 터치 이벤트 경로/레이어 충돌**
   - Android WebView에서 상단 컨트롤 영역의 hit-test가 불안정
   - 일부 버튼만 무반응(`App Info`는 동작, 나머지 3개 무반응)이라는 점이 구조적 레이어/이벤트 경로 문제를 뒷받침

2. **간접 원인(안정성 저하): `speechSynthesis.cancel` 전역 예외**
   - 예외가 반복되며 전체 UI 반응성을 악화시킬 수 있음

---

## 4) 적용한 해결 조치

## 4-1) 안정성 조치 (음성 API 예외 제거)

- `window.speechSynthesis` 접근을 안전 래퍼로 보호
- `cancel()`/`speak()` 호출에 `try/catch` 적용
- `voiceschanged` 리스너 등록/해제 시 메서드 존재 여부 확인

효과:
- `undefined.cancel` 전역 예외 제거
- 시뮬레이션 중지/음성 재생 경로에서 JS 크래시 방지

## 4-2) 버튼 입력 조치 (핵심)

- 상단 4개 버튼에 터치 경로 보강:
  - `onTouchEnd`에서 액션 직접 실행
  - `onPointerDown`/`onTouchStart` 전파 제어
  - 내부 아이콘(`svg`, `img`)에 `pointer-events-none` 적용
- 상단 버튼 배치를 `safe-area` 기준 `fixed` 위치로 변경:
  - `env(safe-area-inset-top/left/right)` 반영
  - 상태바/노치/상단 시스템 영역 간섭 최소화

효과:
- Android WebView에서 상단 버튼 터치 입력이 안정적으로 액션까지 도달

## 6) 재발 방지 권고

1. Android WebView에서 상단 고정 컨트롤은 `safe-area + fixed` 배치를 기본 원칙으로 사용
2. 아이콘 중첩 버튼은 `touchend` 경로를 보조로 두고, 아이콘 `pointer-events`는 부모 버튼 전달 기준으로 설계
3. Web API(`speechSynthesis` 등)는 플랫폼별 가용성 차이를 고려해 안전 래퍼를 공통 유틸화
4. 버튼 이슈 재발 시 `elementFromPoint`, `closest('button')`, `pointercancel` 로그를 표준 진단 절차로 사용
