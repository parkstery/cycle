# 경로 거리별 API 호출량 검토 — 100km vs 1km

**작성일:** 2026년 3월 13일  
**대상:** Cycle Simulator (Fitness Pro Mobile GIS)  
**검토 내용:** 사용자가 경로를 탐색한 뒤 주행(시뮬레이션)할 때, **100km 경로** 사용자와 **1km 경로** 사용자가 호출하는 API 수량 차이 (Google·오픈소스 포함)

---

## 1. 전제 조건

- **시나리오:** 사용자가 출발/도착(및 경유)을 입력 → 경로 탐색 1회 → **Go 클릭 후 주행 시뮬레이션을 끝까지 실행**
- **거리뷰(Street View):** 활성화 상태로 주행한다고 가정 (초기 prefetch + 주행 중 슬라이딩 prefetch 모두 발생).
- **경로 밀도:** OSRM 경로를 10m 간격으로 보간한 `densifiedPath` 기준 (1km ≈ 100 포인트, 100km ≈ 10,000 포인트).
- **초기 거리뷰:** 속도 ≥40 km/h이면 300m, &lt;40 km/h이면 100m 구간을 10m 간격으로 prefetch.
- **슬라이딩 prefetch:** 주행 중 캐시 끝 근처(currentIdx ≥ lastValid − 100)에서 **한 번에 400m 구간**, 10m 간격으로 추가 수집.

---

## 2. 경로 길이와 무관한 API (1회 또는 고정)

다음은 **경로가 1km이든 100km이든 호출 횟수가 동일**합니다.

| 구분 | API/서비스 | 1km 경로 | 100km 경로 | 비고 |
|------|------------|----------|------------|------|
| **경로 탐색** | OSRM (`/api/osrm-route`) | 1회 | 1회 | 출발·도착·경유 좌표 1회 전송 |
| **지오코딩** | Nominatim (`/api/nominatim-search` 등) | 2~5회 | 2~5회 | 출발·도착·경유 주소→좌표, 경로 1회당 동일 |
| **고도** | Open-Elevation (`/api/elevation` POST) | 1회 | 1회 | 경로당 100샘플 고정, 1회 POST |
| **Google Maps 스크립트** | Maps JavaScript API 로드 | 1회 | 1회 | 세션당 1회 |
| **Google 지도 타일** | 정적/동적 타일 | 사용량 유사 | 사용량 유사 | 줌/이동에 따름, 경로 길이만으로는 차이 없음 |

**정리:** 오픈소스(OSRM, Nominatim, Open-Elevation)와 Google 중 “경로 1회 계산”에 해당하는 호출은 **1km와 100km가 동일**합니다.

---

## 3. 경로 길이에 비례하는 API — Google Street View

**차이가 나는 부분은 Google Street View(`getPanorama`) 하나입니다.**

### 3.1 호출 구조 (코드 기준)

- **초기 prefetch (PREPARING):**  
  `maxDistanceM = 300`(또는 100)m, `intervalM = 10`  
  → 300m일 때 **31개 샘플**, 각 샘플당 `findStreetViewInDirection`(1회) 또는 실패 시 `findStreetView`(1회) 등으로 **샘플당 1~3회** `getPanorama` 호출.
- **주행 중 슬라이딩 prefetch (RUNNING):**  
  캐시 끝 근처에서 `fromM ~ fromM+400`m, 10m 간격 → **400m당 40개 샘플**, 샘플당 1~3회 `getPanorama`.

즉, **거리(샘플 수)**에 비례해서 `getPanorama` 호출 수가 늘어납니다.

### 3.2 1km 경로 — 주행 끝까지 실행 시

| 구간 | 거리 | 샘플 수(10m 간격) | getPanorama (추정) |
|------|------|-------------------|--------------------|
| 초기 prefetch | 300m | 31 | 31 ~ 93 |
| 슬라이딩 1차 | 310m ~ 710m | 40 | 40 ~ 120 |
| 슬라이딩 2차 | 720m ~ 1000m | 28 | 28 ~ 84 |
| **합계** | 1km | **약 99** | **약 100 ~ 300** |

- 보수적(대표) 추정: **약 200회** (샘플당 평균 약 2회).

### 3.3 100km 경로 — 주행 끝까지 실행 시

| 구간 | 거리 | 샘플 수(10m 간격) | getPanorama (추정) |
|------|------|-------------------|--------------------|
| 초기 prefetch | 300m | 31 | 31 ~ 93 |
| 슬라이딩 | (100,000 − 300)m ÷ 400m ≈ **250회** × 40샘플 | **약 10,000** | **10,000 ~ 30,000** |
| **합계** | 100km | **약 10,031** | **약 10,050 ~ 30,100** |

- 대표 추정: **약 12,000 ~ 15,000회** (샘플당 평균 1.2~1.5회 가정).

### 3.4 1km vs 100km 요약 (Street View)

| 항목 | 1km 경로 | 100km 경로 | 비율(대략) |
|------|----------|------------|------------|
| getPanorama 호출 수 (대표) | **약 200회** | **약 12,000~15,000회** | **약 60~75배** |

- 초기 300m는 고정이므로, **길이가 길수록 “슬라이딩 prefetch” 비중이 커져** 호출 수는 거의 **경로 길이에 비례**합니다.
- 100km 사용자는 1km 사용자 대비 **Google Street View API 호출만 약 60~75배** 많습니다.

## 4. 서비스별 비교 요약표

| 서비스 | 1km 경로 탐색+주행 | 100km 경로 탐색+주행 | 차이 |
|--------|--------------------|----------------------|------|
| **OSRM** (Vercel 경유) | 1회 | 1회 | 없음 |
| **Nominatim** (Vercel 경유) | 2~5회 | 2~5회 | 없음 |
| **Open-Elevation** (Vercel 경유) | 1회 | 1회 | 없음 |
| **Google Maps (스크립트/타일)** | 1 + 타일 | 1 + 타일 | 없음 |
| **Google Street View (getPanorama)** | **약 200회** | **약 12,000~15,000회** | **약 60~75배** |

---

## 5. 결론 및 권장

- **오픈소스·Vercel API(OSRM, Nominatim, Open-Elevation):** 경로 1회당 호출 수는 **1km와 100km가 동일**하므로, 거리만으로는 비용/트래픽 차이가 없음.
- **Google:** Maps 스크립트·지도 타일은 동일하고, **Street View `getPanorama`만 경로 길이에 비례**하여 증가.
- **비용·쿼터:** 100km 주행 사용자는 1km 주행 사용자 대비 **Google Street View 호출이 약 60~75배** 많으므로, 장거리 사용자가 많을수록 Google Maps Platform 중 **Street View API 사용량·비용**이 크게 늘어남.
- **권장:**  
  - 장거리(예: 50km 이상) 구간에 대해 “거리뷰 미리보기 구간 제한”(예: 처음 5km만 prefetch) 또는 “거리뷰 옵트인” 안내를 두면 Street View 호출을 줄일 수 있음.  
  - 사용량/비용 모니터링 시 **경로 거리 분포**와 **Street View 활성화 비율**을 함께 보는 것이 유리함.
