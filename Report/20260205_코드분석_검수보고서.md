## 1. 요약

- **프로젝트**: React + TypeScript 기반 자전거 시뮬레이터 (Google Maps Street View, OSRM 경로, Open-Elevation 표고, AI 코칭)

- **조치 완료**: 타입 정의 정리(geoUtils), 웨이포인트 제거 시 마커 라벨 동기화 버그 수정

## 2. 아키텍처 및 구조

| 구분 | 내용 |
|------|------|
| **엔트리** | `index.tsx` → `App.tsx` (단일 루트 컴포넌트) |
| **상태** | React useState/useRef, localStorage(즐겨찾기·최근 검색) |
| **외부 연동** | Google Maps JS API(맵·Street View), OSRM(경로), Nominatim(지오코딩), Open-Elevation(표고) |
| **API** | Vite proxy → `/api/nominatim-*`, `/api/osrm-route` (Vercel serverless 형식) |

**강점**
- 경로/표고/거리뷰를 OSRM·Open-Elevation·Nominatim으로 처리해 Google 의존도를 낮춤.
- 거리뷰 이중 버퍼·프리페치·온디맨드 세그먼트로 주행 중 API 호출 최소화.
- 코칭은 로컬 로직 + phraseManifest로 TTS만 사용해 외부 AI 비용 없음.

**개선 권장**
- `App.tsx`가 약 1,180줄로 과도하게 큼. 경로 입력/거리뷰/시뮬레이션/오디오·코칭 등을 훅·하위 컴포넌트로 분리하면 유지보수와 테스트에 유리함.

## 3. 타입 및 코드 품질

### 3.1 조치 완료: `services/geoUtils.ts`

- **문제**: `getLatLng`·`computeDistanceBetween` 등에서 `lat`/`lng`를 숫자와 함수 타입으로 중복 선언한 객체 타입 사용. TypeScript에서 후행 속성만 유효해 의도와 다르게 해석될 수 있음.
- **조치**: `LatLngLike` 타입을 `{ lat?: number; lng?: number } | { lat: () => number; lng: () => number }` 형태로 정의하고, 해당 인자에 일괄 적용함.

### 3.2 조치 완료: 웨이포인트 제거 시 마커 라벨

- **문제**: `handleRemoveWaypoint(idx)`에서 해당 마커만 제거하고 배열을 splice한 뒤, 남은 마커의 라벨을 갱신하지 않아 1, 3, … 처럼 번호가 끊겨 보일 수 있음.
- **조치**: splice 후 `waypointMarkers.current`를 순회하며 `setOptions({ label: { text: (i+1).toString(), ... } })`로 1, 2, … 로 재정렬하도록 수정함.

### 3.3 기타 타입

- **Google Maps**: `declare var google: any` 사용. 필요 시 `@types/google.maps` 도입으로 타입 안정성 확보 권장.
- **types.ts**: `RouteInfo`, `PanoDataItem`, `CachedCoachingItem` 등 일관되게 정의되어 있음.

## 5. API·외부 서비스

### 5.1 Nominatim (`services/nominatim.ts`)

- 1 req/s 쿼리(throttle), User-Agent 설정, 역지오코딩/검색 캐시 적용으로 정책·성능 고려됨.
- Plus Code 파싱 후 짧은 코드는 locality로 참조 좌표 조회; 실패 시 `(46.6, 8.0)` 기본값 사용. 동작은 명시해 두는 것이 좋음.

### 5.2 Open-Elevation

- 브라우저에서 `api.open-elevation.com`으로 직접 POST. CORS 허용 여부에 따라 환경별 이슈 가능성 있음. 문제 시 Vercel 함수 등 프록시 추가 검토.

### 5.3 API 라우트 (`api/*.js`)

- `osrm-route.js` 79행: `e.message` 사용. `catch (e)`에서 `e`가 Error가 아닐 수 있으므로 `String(e?.message ?? e)` 등으로 통일 권장.
- 메서드 검사(GET), 필수 파라미터 검증 있음. 에러 시 502와 메시지 반환 적절함.

## 6. 성능·사용자 경험

- **거리뷰**: GOOGLE → DEFAULT 폴백, 이중 버퍼·status_changed 대기·150ms 지연으로 전환 시 검은 화면 완화.
- **경로 재사용**: `lastRouteRequestRef`와 `inputsMatch`로 동일 입력 시 Go 버튼에서 재탐색 없이 시뮬레이션만 시작.
- **디버그 로그**: `[CALCULATE_ROUTE_CALL]`, `[ELEVATION_API_CALL]` 등이 프로덕션에도 출력됨. `import.meta.env.DEV` 분기 또는 빌드 시 제거 권장.

## 7. 기타 이슈 및 권장 사항

1. **PLAYLIST**: Dropbox raw URL 하드코딩. 링크 만료·변경 시 재배포 필요. 설정(환경 변수/설정 파일) 분리 권장.
2. **배경 음악 오류**: `playRandomMusic` 내 `console.log("Audio autoplay blocked or failed", e)`는 개발 시에만 남기거나 로깅 레벨로 제어 권장.
3. **ElevationChartView**: `refLineX`가 `data.length - 1`을 넘지 않도록 이미 `Math.floor`로 계산되어 있음. `pathLength`가 0이면 분모 0 주의는 있으나 현재 분기로 0 반환해 문제 없음.
4. **의존성**: `package.json`에 react, recharts, lucide-react 등 명시됨. `node_modules` 미설치 상태에서 검수했으며, 배포 전 `npm install` 및 빌드·스모크 테스트 권장.
