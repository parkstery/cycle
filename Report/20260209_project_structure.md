# Project Structure Analysis: Cycle Simulator

## 1. Project Overview
**Name**: Fitness Pro Mobile GIS (Cycle Simulator) / `fitness-pro-mobile-gis`
**Type**: Single Page Application (SPA) with Serverless Functions
**Tech Stack**:
- **Frontend**: React 18, TypeScript, Vite 5, Tailwind CSS
- **Maps & Data**: Google Maps Platform (Maps, Street View), OpenStreetMap (Nominatim), Open-Elevation
- **Deployment**: Vercel (Frontend + API Routes)

## 2. Directory Structure

### Root Directory
- **`App.tsx`**: The main application component. Handles map initialization, route planning, simulation logic (Street View playback), and UI controls.
- **`About.tsx`**: The "About" modal component displaying app information, credits, and legal notices.
- **`index.html`**: Entry point for the Vite app.
- **`main.css`**: Global styles and Tailwind directives.
- **`types.ts`**: TypeScript type definitions shared across the app (RouteInfo, SimulationState, etc.).
- **`vite.config.ts`**: Vite configuration.
- **`tailwind.config.js`**: Tailwind CSS configuration.
- **`vercel.json`**: Vercel deployment configuration (rewrites for API paths).

### `/api` (Serverless Functions)
Houses Vercel Serverless Functions to proxy requests and handle backend logic, avoiding CORS issues and hiding API keys where possible.
- **`nominatim-search.js`**: Proxies requests to Nominatim for place search.
- **`nominatim-reverse.js`**: Proxies requests for reverse geocoding (coord -> address).
- **`osrm-route.js`**: Proxies requests to OSRM for route calculation (cycling/walking paths).

### `/services` (Business Logic)
TypeScript modules handling core application functionality.
- **`aiCoach.ts`**: Logic for the AI Coaching feature. Analyzes slope/elevation changes to generate coaching tips and resistance levels.
- **`audioCache.ts`**: Manages pre-loading and playback of coaching audio files.
- **`geoUtils.ts`**: Geometric calculations (distance, heading, decoding polylines).
- **`nominatim.ts`**: Client-side service wrapper for calling the Nominatim API endpoints.
- **`openElevation.ts`**: Service for fetching elevation data along a path.
- **`phraseManifest.ts`**: Central registry for coaching text phrases and resistance band mappings.
- **`plusCode.ts`**: Likely handles Open Location Code (Plus Code) support (though not deeply analyzed in this pass).
- **`choaching/`**: Contains source MP3 files for coaching tips. (Note: The app likely uses the copies in `public/choaching` for playback).

### `/public` (Static Assets)
Files served directly to the client.
- **`choaching/`**: Directory containing MP3 audio files (`tip_*.mp3`, `res_*.mp3`) used for AI coaching voiceovers.
- **`icon-512.png`**: App icon.
- **`cycle-road.png`**: Street View toggle button icon.
- **`cycling-position-marker.png`**: Custom map marker for the cyclist's position.
- **`manifest.json`**: Web App Manifest for PWA support.

### `/dist`
Contains the build output (production-ready files) generated by `npm run build`.

## 3. Key Observations
- **Duplicate Audio Files**: The `choaching` folder exists in both `services` and `public`. The application logic (`audioCache.ts`) points to `/choaching/`, meaning the `public` folder is the active source for the web app. The `services` copy might be a dev resource or backup.
- **Typo**: `choaching` seems to be a typo for `coaching`.
- **Hybrid Architecture**: heavily relies on client-side logic (`App.tsx` is vast ~2000 lines) but offloads cross-origin data fetching (OSRM, Nominatim) to `/api` proxies.
