**작성일:** 2026년 2월 4일  
**프로젝트명:** Cycle Simulator (fitness-pro-mobile-gis)  
**배포:** Vercel (SPA + Serverless API)

## 1. 전반적인 보고서 개요

본 프로젝트는 **자전거·도보 경로 시뮬레이션**과 **거리뷰(Street View) 연동 주행**, **고도 기반 AI 코칭**, **경로 탐색·장소 검색**을 하나의 웹 앱에서 제공하는 **PWA 형태의 모바일 GIS 애플리케이션**이다.

- **핵심 가치:** 출발지·도착지·경유지를 입력하면 OSRM으로 경로를 계산하고, Open-Elevation으로 고도를 조회한 뒤, 주행 시뮬레이션 중 Google Street View로 실제 도로 전경을 보여주며, 경사도에 따른 코칭 멘트(TTS)와 배경 음악을 재생한다.
- **아키텍처:** 클라이언트(React SPA) 중심이며, 경로/지오코딩은 **Vercel Serverless API**를 통해 Nominatim·OSRM을 호출하고, 고도·거리뷰·지도는 **브라우저에서 외부 API**를 직접 호출한다.
- **비용 절감:** 경로 탐색은 Google Directions 대신 **OSRM**, 주소/역지오코딩은 **Nominatim**, 고도는 **Open-Elevation**을 사용하여 Google 의존도를 낮추었다. AI 코칭은 **로컬 규칙 + phraseManifest + 브라우저 TTS**로 Gemini API를 사용하지 않는다. **(코드 검증: 현재 소스에는 Google Geocoding API·Maps Elevation API 호출이 없으며, 지오코딩·고도는 오픈소스만 사용. 콘솔 사용량은 §4.1 참고.)**

이 문서에서는 **기술 스택**, **기능 요소**, **기능별 사용 API**, **기능별 콘트롤 명세**, **트래픽 량**을 정리한다.

### 4.1 코드 검증 — 지오코딩·고도 API (사실 확인)

**현재 이 저장소의 소스코드만 기준으로 한 분석 결과:**

| 구분 | 코드에서 사용하는 API | 호출 위치 (파일:행) | Google API 호출 여부 |
|------|------------------------|---------------------|------------------------|
| **지오코딩** | **Nominatim** (오픈소스) | 지도 클릭: `nominatim.reverse(lat, lng)` — `App.tsx` 585행 | **없음** (`google.maps.Geocoder` 미사용) |
| | | 장소 검색: `nominatim.search(query)` — `App.tsx` 1442행 | **없음** |
| | | 주소→좌표(경로 계산): `nominatim.addressToCoord(addr)` — `App.tsx` 1126행 | **없음** |
| **고도** | **Open-Elevation** (오픈소스) | 경로 고도: `openElevation.getElevationAlongPath(path, 100)` — `App.tsx` 1174행 | **없음** (`google.maps.ElevationService` 미사용) |

- **Maps 스크립트 로드:** `App.tsx` 631행 — `maps/api/js?key=...&loading=async&callback=...` 만 사용. `libraries=geocoder,elevation` 파라미터 **없음**.
- **결론:** 현재 코드 상으로는 **Google Geocoding API**와 **Google Maps Elevation API**를 호출하는 부분이 **전혀 없습니다.** 지오코딩은 `services/nominatim.ts`(역지오코딩·검색·주소→좌표), 고도는 `services/openElevation.ts`(api.open-elevation.com POST)만 사용합니다.

**Google Cloud 콘솔에서 Geocoding / Elevation 사용량이 보이는 경우:**

콘솔에 Geocoding API·Maps Elevation API 사용량(예: 326건, 169건)이 집계된다면, **현재 이 리포지토리 코드만으로는 발생하지 않습니다.** 가능한 원인은 아래를 점검하는 것이 좋습니다.

1. **배포된 빌드가 과거 버전인 경우** — Vercel 등에 이전에 배포된 번들이 남아 있고, 그 버전이 아직 Google Geocoder / ElevationService를 호출하고 있을 수 있음. 최신 코드로 재배포 후 사용량 추이 확인.
2. **동일 API 키를 쓰는 다른 앱·페이지** — 같은 Google Cloud 프로젝트(API 키)를 다른 서비스에서 사용 중이면 해당 요청도 함께 집계됨.
3. **캐시된 구버전 클라이언트** — 사용자 브라우저가 예전 JS 번들을 캐시해 두었다면, 구 코드가 Google API를 호출할 수 있음.

**보고서 기술 방침:** 위와 같이 **코드 기준 사실(Nominatim·Open-Elevation만 사용, Google Geocoding/Elevation 미호출)**을 우선 기록하고, 콘솔 사용량은 배포 버전·API 키 사용처 확인이 필요함을 명시합니다.

## 6. 트래픽 량 조사

### 6.1 아키텍처 요약

- **Vercel:** (1) 정적 자산(HTML, JS, CSS 청크, manifest, sw.js) 제공, (2) Serverless API: `/api/nominatim-search`, `/api/nominatim-reverse`, `/api/osrm-route` — 클라이언트는 같은 오리진으로 `/api/*`만 호출하고, 각 함수가 Nominatim/OSRM을 호출한다.
- **브라우저 직접 호출:** Google Maps JS 로드, 지도 타일·Street View, Open-Elevation POST, Dropbox MP3 — Vercel을 거치지 않는다.

### 6.2 Vercel으로 들어가는 요청 (세션 기준)

| 요청 유형 | URI 예시 | 빈도 |
|-----------|----------|------|
| 초기 로드 | `/`, `/index.html` | 1회 |
| JS/CSS 청크 | `/assets/*-[hash].js`, `*.css` | 초기 1회분 (청크 수에 따라 4~8건 수준) |
| manifest / sw | `/manifest.json`, `/sw.js` | 필요 시 각 1회 |
| **API** | `/api/nominatim-search` | 장소 검색 1회당 1회 (경로 계산 시 출발+도착+경유 주소 변환 시에도 호출, 캐시 시 스킵) |
| | `/api/nominatim-reverse` | 지도 클릭 1회당 1회 (캐시 시 스킵) |
| | `/api/osrm-route` | 경로 계산 1회당 1회 |

- **세션당 Vercel 요청:** 정적 약 4~8건 + (검색·클릭·경로 계산 횟수에 따른 API 건수). 경로 1회 + 검색 2회 + 클릭 3회 가정 시: 약 4~8 + 1 + 2 + 3 = **약 10~14건** 수준.

### 6.3 브라우저 → 외부 서비스 (Vercel 미경유)

| 대상 | 트리거 | 예상 빈도 |
|------|--------|-----------|
| **Google Maps JS** | 앱 로드 | 1회 |
| **Google Maps 타일/리소스** | 지도 표시·이동·줌 | 사용에 따라 수십~수백 건 |
| **Google Street View** | PREPARING: 구간 선로딩(200m, 10m 간격) → getPanorama 다수; RUNNING: 캐시 우선, 부족 시 온디맨드 세그먼트 또는 실시간 getPanorama | 선로딩 시 20회 내외 + 주행 중 캐시 미스 시 추가 |
| **Open-Elevation** | 경로 확정 후 고도 조회 | 경로 1회당 1회 POST (경로별 캐시 적용) |
| **Dropbox** | 시뮬레이션 중 배경음 재생 | 트랙 수 × 재생 횟수 (스트리밍) |

| 경로 1회 계산(출발·도착·경유 주소 입력) | 1 (osrm-route) + 필요 시 2~4 (nominatim-search) | 0 | 1 (POST) | 0 |
| 지도 클릭 1회 | 1 (nominatim-reverse, 캐시 시 0) | 0 | 0 | 0 |
| 장소 검색 1회 | 1 (nominatim-search, 캐시 시 0) | 0 | 0 | 0 |
| 주행 시작(PREPARING) | 0 | Street View 선로딩 다수(약 20회 수준) | 0 | 0 |
| 주행 중(RUNNING) | 0 | SV 캐시 미스 시 getPanorama | 0 | Dropbox MP3 |

### 6.5 트래픽·비용 관련 정리

- **Vercel:** 정적 배포 + Serverless 3개 API. API 호출은 사용자 행동(검색, 클릭, 경로 계산)에 비례하며, Nominatim 1 req/s 제한을 위해 클라이언트에서 스로틀(1.1초) 및 캐시 적용.
- **Google:** Maps JS(세션 1회) + 지도 타일 + Street View가 주요 트래픽. Street View는 선로딩·캐시·온디맨드로 RUNNING 중 호출을 줄이는 구조.
- **Open-Elevation:** 경로당 1회 POST, 경로 캐시로 동일 경로 재계산 시 호출 생략.
- **OSRM:** 공개 서비스 사용, Vercel 함수가 프록시하므로 브라우저→Vercel 1회, Vercel→OSRM 1회.
