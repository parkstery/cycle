# 경로 전환 시 거리뷰 stop 상태 유지 — 추가 해결방안

## 현상 (재발)

- 주행 중 My Route에서 경로를 불러온 뒤 Go를 눌러도, **이전 주행 경로의 거리뷰가 stop 상태로 유지**된 채, **맵에는 불러온 경로를 주행 중인 것처럼** 보이는 경우가 여전히 발생함.
- 이미 적용한 조치: 경로(path) 설정 직후 시뮬레이션·ref 리셋 + 새 경로 시작점으로 `setPanoramaView(startPos, heading)` 호출.

---

## 여전히 발생할 수 있는 원인

### 1. `setPanoramaView` 가 비동기·미대기

- `setPanoramaView(startPos, heading)` 는 내부에서 `getPanoramaWithFallback(...).then(...)` 만 호출하고 **await 하지 않음**.
- 실제 파노라마 스왑은 “status OK 후 150ms” 또는 **최대 1500ms 폴백** 뒤에 일어남.
- 그 사이에는 **이전 경로의 마지막 파노라마가 그대로** 보일 수 있음.
- 네트워크 지연·새 경로 시작점 주변 커버리지 부족 시 응답이 늦어지거나 실패하면, **이전 거리뷰가 stop 상태로 오래 유지**됨.

### 2. 파노라마 스왑 대기열·상태 충돌

- 이전 주행에서 **스왑 대기(pendingSwapTimeout / scheduleSwapAfterOk)** 가 아직 남아 있는 상태에서 새 경로로 `setPanoramaView` 를 호출하면, 새 요청이 이전 스왑과 겹치거나 이전 스왑이 나중에 적용되어 **옛 파노가 다시 보일** 수 있음.
- 리셋 시 pending 타임아웃을 clear하는 로직이 `setPanoramaView` 진입 시에만 있으면, **경로 전환 직후 한 번에 여러 번** 호출되거나, ref만 리셋하고 파노라마 인스턴스는 그대로 둔 경우 **화면은 이전 pano 유지**일 수 있음.

### 3. My Routes 선택 시점과 Go 시점 사이

- **handleLoadFavorite** 호출 시에는 **route 상태는 그대로**(이전 경로)이고, origin/destination/waypoints 만 바뀜.
- 사용자가 “경로만 불러온” 직후 잠시 맵을 보다가 Go를 누르므로, 그 사이에도 시뮬레이션은 **이전 경로**로 계속 진행 중.
- Go → `calculateRoute` 에서 리셋을 하더라도, **리셋 직후 즉시** “새 경로의 첫 거리뷰”가 보이지 않고 **setPanoramaView 완료까지 지연**되면, 사용자 체감상 “불러온 경로 주행 중인데 거리뷰만 stop”으로 보일 수 있음.

### 4. 단일 경로 전환 지점이 아닌 경우

- 새 path를 넣는 코드 경로가 **calculateRoute 밖에도** 있으면(예: 저장된 경로를 path만 복원하는 경로), 그곳에서는 리셋·setPanoramaView 가 호출되지 않아 **맵만 새 경로, 거리뷰는 옛날** 상태가 됨.

---

## 추가 해결방안 (코드 작성 없이 제안만)

### 방안 A: 경로 전환 직후 “거리뷰 화면”을 일시 숨기기

- **새 path를 설정한 직후**, `setPanoramaView` 를 호출하기 전 또는 호출과 동시에:
  - 거리뷰를 그리는 컨테이너(div)를 **opacity 0** 또는 **visibility: hidden** 으로 두거나,
  - 그 위에 **“Loading route…” / “Preparing Street View…”** 같은 오버레이를 **항상** 켜서 **이전 파노라마가 보이지 않게** 함.
- **새 경로의 첫 파노라마가 실제로 스왑되어 표시된 뒤**에만 (예: setPanoramaView 의 스왑 콜백에서, 또는 panoData[0] 적용 직후) 오버레이를 제거하고 거리뷰를 다시 보이게 함.
- 효과: “이전 경로 거리뷰가 stop 상태로 보이는” 구간 자체를 제거.

### 방안 B: setPanoramaView 완료를 기다린 뒤 다음 단계 진행

- `setPanoramaView(startPos, heading)` 를 **Promise를 반환**하도록 바꾸고(내부에서 getPanoramaWithFallback + 스왑 완료 시 resolve),
- 경로 전환 시 **await setPanoramaView(...)** 한 뒤에만:
  - `setAppPhase('PREPARING')` 및 preFetchStreetViewData 시작,
  - 또는 (autoStart 시) 카운트다운 시작
- 효과: “맵은 새 경로인데 거리뷰는 아직 옛날”인 타이밍을 구조적으로 제거.

### 방안 C: My Routes 선택 시점에 즉시 “주행 중” 상태 정리

- **handleLoadFavorite** 호출 시, **현재 시뮬레이션이 주행 중이면**:
  - `setSimulation({ isActive: false, currentIndex: 0 })` 로 즉시 중단,
  - `svDisplayPathIndexRef`, `lastDisplayedPanoPathIndexRef` 등 거리뷰 ref 초기화,
  - (선택) 거리뷰를 **빈 화면** 또는 **“Select route and press Go”** 같은 안내로 전환(파노라마 visible: false 또는 오버레이 표시).
- 효과: “My Route만 불러온 상태”에서도 이전 경로 주행·거리뷰가 더 이상 진행되지 않고, Go를 누르면 새 경로만 보이게 됨.

### 방안 D: 경로 식별자(routeId)로 “경로가 바뀐 순간”만 강제 동기화

- **route** 객체에 **routeId** (예: `origin+destination+waypoints` 해시 또는 매 회 경로 설정 시 증가하는 숫자)를 넣고,
- 시뮬레이션·거리뷰를 갱신하는 쪽(이펙트 또는 틱)에서 **“현재 routeId가 이전과 다르면”**:
  - 거리뷰 ref 전부 초기화,
  - **현재 route의 시작점으로만** 파노라마를 한 번 설정하고, 그 전에는 거리뷰 인덱스 진행을 하지 않음.
- 경로 전환 진입점(calculateRoute, 저장 경로 로드 등)이 여러 개여도 **한 곳(routeId 변경 감지)** 에서만 “경로 바뀜 → ref 초기화 + 첫 거리뷰 설정”을 하면, 놓치는 경로가 없음.

### 방안 E: 파노라마 인스턴스까지 “초기화”하는 옵션

- 경로 전환 시 **리셋**할 때, ref만 0으로 두지 말고:
  - **pendingSwapTimeout / pendingSwapFallback** 을 clear하는 것은 물론,
  - **현재 보이는 파노라마(panorama1/2)의 visible을 false** 로 두었다가, 새 경로의 첫 파노가 준비된 뒤에만 다시 true 로 두는 방식.
- 효과: 이전 파노가 “한 프레임이라도” 다시 그려질 여지를 줄임.

### 방안 F: prefetch 완료·첫 파노 적용 후에만 “주행 중” 표시

- 이미 “path만 설정된 동안에는 시뮬레이션 중단”은 적용된 상태.
- 추가로, **autoStart** 인 경우:
  - preFetchStreetViewData 완료 후 **setPanoramaViewByPanoId(firstPano)** (또는 setPanoramaView)가 **실제로 스왑 완료될 때까지** 기다린 뒤,
  - 그 다음에만 **setSimulation({ isActive: true, ... })** 및 카운트다운 시작.
- 효과: 사용자가 “주행 중”으로 인식하는 시점에는 **항상 새 경로의 거리뷰**가 이미 표시된 상태가 됨.

## 권장 조합 (추가 적용 시)

| 우선순위 | 방안 | 요약 |
|----------|------|------|
| 1 | **A** | 경로 전환 직후 거리뷰를 숨기거나 오버레이로 가려, 이전 거리뷰가 stop 상태로 보이지 않게 함. |
| 2 | **C** | My Routes 선택 시 즉시 시뮬레이션·거리뷰 ref 리셋(및 선택적으로 거리뷰 비표시), Go 전에도 상태 정리. |
| 3 | **B** 또는 **F** | setPanoramaView(또는 첫 파노 적용) 완료를 기다린 뒤 PREPARING/주행 시작으로 넘어가, “맵만 새 경로” 구간 제거. |
| 4 | **D** | routeId로 경로 전환을 한 곳에서만 감지해, 모든 진입 경로에서 동일하게 리셋·첫 거리뷰 적용. |

이렇게 하면 “주행 중 My Route 불러오기 → Go” 후에도 **맵과 거리뷰가 모두 새 경로 기준**으로 맞고, 이전 경로 거리뷰가 stop 상태로 남아 보이는 현상을 추가로 줄일 수 있습니다.
