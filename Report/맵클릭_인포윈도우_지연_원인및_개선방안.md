# 맵 클릭 시 인포 윈도우 지연 — 원인 및 지연 시간 줄이는 방안

## 1. 현재 동작 요약

맵(또는 경로)을 클릭하면:

1. **역지오코딩**: Nominatim API로 좌표 → 주소 조회  
2. **표고 조회**: Open-Elevation API로 해당 점 고도 조회  
3. **Promise.all**로 두 요청을 **동시에** 보냄  
4. **두 응답이 모두 도착한 뒤** 한 번에 `setClickedLocation` 호출 → 인포 윈도우 표시  

즉, **팝업은 “두 API가 모두 끝난 시점”에만** 뜹니다.

---

## 2. 지연이 길어지는 원인

### 2.1 두 개의 외부 API 대기

- **Nominatim (역지오코딩)**  
  - 네트워크 왕복 + 서버 처리 시간 (수백 ms ~ 1초 이상)  
  - 정책 준수를 위한 **1 req/s 스로틀**: 이전 요청 후 1.1초 미만이면 **그만큼 대기 후** 요청  
  - 직전에 검색/역지오코딩이 있으면 **최대 약 1.1초**가 그대로 추가됨  

- **Open-Elevation (표고)**  
  - POST 한 번에 1점 조회  
  - 네트워크 왕복 + 서버 처리 (수백 ms ~ 1초 이상, 서버 부하에 따라 더 길어질 수 있음)  

- **Promise.all**  
  - “둘 중 **더 느린 쪽**이 끝날 때까지” 대기  
  - 하나가 0.5초, 다른 하나가 2초면 → 체감 지연은 2초  

→ **두 API + 스로틀**이 겹치면서 **1~3초, 상황에 따라 그 이상**까지 늘어날 수 있음.

### 2.2 첫 클릭 시 캐시 미적중

- **Nominatim**: `reverseCache`가 있지만 키가 `lat,lng`(소수 4자리). **같은 점을 다시 클릭하면** 빠름, **첫 클릭·새 위치**는 항상 API 호출.  
- **Open-Elevation**: 단일 점도 `pathCacheKey`로 캐시하므로 **재클릭 시**는 빠를 수 있음. **첫 클릭**은 항상 API 호출.  

→ **첫 클릭**이 특히 느리게 느껴짐.

### 2.3 “로딩 중” 표시 없음

- 클릭 후 **응답이 올 때까지** 화면에는 아무 반응이 없음.  
- 사용자는 “클릭이 먹었는지” 알 수 없어 **체감 대기 시간이 더 길게** 느껴짐.

---

## 3. 지연 시간을 줄이는 방안

### 방안 1: 즉시 팝업 띄우고, 주소·표고는 비동기로 채우기 (체감 지연 최우선)

- **클릭 직후** 좌표만이라도 넣어서 **인포 윈도우를 바로** 띄움.  
  - 예: 제목은 `"Loading..."` 또는 `"37.5512, 126.9882"`, 표고는 `"—"` 또는 `"Loading..."`  
- **백그라운드**에서 Nominatim + Open-Elevation 호출은 그대로 진행.  
- 각각 응답 오는 대로 **주소 / 표고만 갱신** (한 번씩 `setClickedLocation`으로 부분 갱신하거나, 주소·표고만 state로 따로 두고 갱신).  

**효과**:  
- “클릭했는데 아무 일도 안 난다”는 느낌 제거.  
- 실제 API 시간은 그대로여도 **체감 지연이 크게 줄어듦**.  

**구현 포인트**:  
- 클릭 시 `setClickedLocation({ lat, lng, address: 'Loading...', elevation: null, ... })` 등으로 **즉시** 표시.  
- `Promise.all` 대신 각각 `.then`으로 **도착하는 대로** 해당 필드만 업데이트.

---

### 방안 2: 표고는 나중에 로드 (필수 정보만 먼저)

- **1차**: 역지오코딩만 기다려서 **주소 + 좌표**로 먼저 팝업 표시.  
- **2차**: Open-Elevation은 그 다음에 요청하고, 도착하면 **표고만 추가/갱신**.  

**효과**:  
- 팝업이 뜨는 시점 = **Nominatim 1개 응답만** 기다리면 됨.  
- 표고 API가 느려도 “주소는 이미 보임”이라 체감이 나아짐.  
- 필요하면 표고 자리는 “—”, “Loading…” 등으로 두었다가 나중에 숫자로 바꿈.  

**구현 포인트**:  
- `Promise.all` 제거.  
- `nominatim.reverse(...).then(...)` 에서 먼저 `setClickedLocation({ ..., address, elevation: null })`.  
- `openElevation.getElevationAlongPath([...], 1).then(...)` 에서는 `setClickedLocation(prev => ({ ...prev, elevation }))` 형태로 **표고만** 갱신.

---

### 방안 3: Nominatim 스로틀 회피(또는 완화)

- **현재**: 모든 Nominatim 호출이 **공용** 1 req/s 스로틀을 타서, 직전 요청 후 1.1초 안이면 무조건 대기.  
- **개선**:  
  - “맵 클릭으로 인한 역지오코딩”만 **별도 스로틀/큐**를 두거나,  
  - 정책상 허용 가능하다면 **클릭 시 역지오코딩**은 스로틀을 짧게(예: 300ms) 하거나, 최초 1회는 대기 없이 보내는 방식 검토.  

**효과**:  
- 다른 기능(검색 등) 사용 직후 맵을 클릭해도, **최대 1.1초 대기**를 줄일 수 있음.  
- 정책 위반이 되지 않도록 Nominatim 사용 정책 확인 필요.

---

### 방안 4: 캐시 활용 강화

- **역지오코딩**:  
  - 캐시 키를 소수 4자리 유지하되, **주변 격자**까지 한 번에 요청하는 건 정책상 부담이 있으므로,  
  - “같은 좌표 재클릭”이 이미 캐시로 빠르게 되는지 확인.  
- **표고**:  
  - 단일 점 `[{lat,lng}]`, samples=1 조합이 **캐시 키에 제대로** 들어가는지 확인.  
  - 동일 점 재클릭 시 캐시에서 바로 반환되면, 두 번째부터는 API 없이 즉시 표시 가능.  

**효과**:  
- 첫 클릭은 여전히 두 API 대기이지만, **같은 위치 재클릭** 시 지연이 거의 사라짐.

---

### 방안 5: 호버 시 프리페치(선택)

- 맵 위 **마우스 호버** 시, 해당 좌표에 대해 **역지오코딩 + 표고**를 미리 요청(디바운스 200~300ms 등).  
- 사용자가 **클릭**했을 때는 이미 캐시에 있으면 **즉시** 팝업 표시.  

**효과**:  
- “클릭 → 바로 팝업”이 될 확률이 높아짐.  
**주의**:  
- 호버만 많이 해도 요청 수가 늘어나므로, 디바운스·호버 영역 제한·캐시 적중률 모니터링이 필요.  
- Nominatim 1 req/s와 맞추려면 호버용 요청도 같은 스로틀을 타도록 해야 함.

---

### 방안 6: 표고 API 대체 또는 생략 옵션

- Open-Elevation이 느린 경우:  
  - 더 빠른 표고 API가 있으면 교체 검토.  
  - 또는 “맵 클릭 인포”에서는 **표고 없이 주소만** 보여 주고, 표고는 “경로 탐색” 등 다른 화면에서만 쓰는 방식.  

**효과**:  
- 클릭 시 기다리는 API가 **하나(Nominatim)**로 줄어들어, 최대 대기 시간이 줄어듦.

---

## 4. 우선 적용 권장 순서

| 순서 | 방안 | 기대 효과 | 구현 부담 |
|------|------|-----------|-----------|
| 1 | **즉시 팝업 + 비동기 채우기** (방안 1) | 체감 지연 대폭 감소 | 낮음 |
| 2 | **주소 먼저, 표고 나중** (방안 2) | 실제 첫 표시 시간 단축 | 낮음 |
| 3 | **캐시 동작 확인** (방안 4) | 재클릭 시 지연 제거 | 낮음 |
| 4 | **Nominatim 스로틀 검토** (방안 3) | 최대 1.1초 추가 대기 완화 | 중간(정책 확인 필요) |
| 5 | 호버 프리페치 / 표고 생략·대체 (방안 5·6) | 추가 개선 | 선택 |

---

## 5. 요약

- **지연 원인**: (1) Nominatim + Open-Elevation **두 API**를 모두 기다린 뒤에만 팝업 표시, (2) Nominatim **1 req/s 스로틀**로 인한 최대 1.1초 추가 대기, (3) 첫 클릭 시 **캐시 미적중**, (4) **로딩 중 표시 없음**.  
- **지연을 줄이는 핵심**: **클릭 직후 팝업을 띄우고**(좌표·로딩 문구라도), **주소는 먼저, 표고는 나중에** 채우며, **캐시와 스로틀**을 정리하면, 실제·체감 모두 개선할 수 있음.
